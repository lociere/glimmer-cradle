# 当前物理拓扑

> 范围：描述当前 tracked source 中真实存在并被 manifest、入口或构建链消费的结构。
> 事实依据：当前 tracked source、package/workspace manifest、部署与 workflow 入口。
> 维护触发：tracked 根、workspace package、入口或部署文件变化时。

本页只描述当前事实，不把 [v2 目标基线](../blueprint/README.md) 写成已落地。
覆盖口径是 tracked 顶层根、package/workspace manifest、关键入口和主要部署链，不是全仓
逐文件抄录。

Platform 的 `configuration` 提供注入 Schema 的 `ConfigurationValidator`，拥有 AJV 编译缓存、
原地默认值填充与错误格式。Kernel 的配置 registry 和产品装配入口消费该机制，并继续从
`contracts/json-schema/` 装配各自 Schema；配置路径、读写、产品类型与策略仍归原 owner。

## 3. 当前边界

- `contracts/` 是唯一 Contract Spine；`protocol/`、legacy generated projection、ZMQ/stdio RPC 与被替代的器官间手写 WebSocket 主线已删除。
- Extension Host 执行容器位于 `hosts/extension-host/` 独立 Node 子进程；Kernel 保留 supervision、权限、catalog、编排和 Projection owner。
- Kernel 物理根为 `domain/application/ports/adapters/runtime/composition`；Cognition 物理根为 `domain/application/ports/adapters/host`。`core/conversation` 已拥有稳定 Binding 解析、Message/Turn、canonical Conversation Log 单写者与 History projection；Kernel 通过 Composition 注入 Platform identity，Cognition Worker 只组合 Conversation Port 与 Experience/Memory 投影。
- Avatar Core 位于 `core/avatar/`，Unity/Cubism Host 位于 `hosts/unity-avatar-host/`；二者通过本地 assembly 单向依赖。
- Config/Extension/Product Document 的 serialized shape 由 `contracts/json-schema/` 拥有；normalizer、默认加载和 view mapping 留在直接 owner。
- Desktop installer 已有 Windows fixed-artifact 任务与 workflow，但 clean Windows
  installer/首启/升级/卸载、签名和公证仍未实机验证。
- `tools/` 只是 grouping root；两个叶子 workspace 均为 private、可测试且不被 runtime、deploy 或发布制品依赖。root `scripts/` 已删除。
