## 部署状态机

```text
acquire host.lock
  -> prepare
  -> replace / restart
  -> readiness
  -> bridge_readiness
  -> commit
  -> committed
```

`host.lock` 与 `.host.lock.guard` 的 inode/FD 必须保持一致。竞争返回 75；不可信路径、锁身份
替换或不能恢复操作前状态返回 78，并把 `recovery_action` 写入 transaction journal。Bridge
先生成 one-shot owner、等待其持锁 ready，再向调用者返回 accepted；响应完成后 ack，旧
Bridge 才可被回收。

`status/logs` 不经过上述状态机。它们只读现有 env，并用当前权限查询 Docker；缺文件或
权限不足按稳定 exit 失败，不运行 sudo。

## 数据与制品

- backup 根按 manual/transaction/restore-safety 分离；transaction retention 不遍历其他根。
- Smoke 在临时目录复制 models/packages；任一 symlink 使准备失败并清场。
- DLQ replay 把真实 payload 写入 dispatcher stdin，只有 receipt 成功后更新记录。
- prepare-runtime 同时比较 input digest 与每个 output 的 path/size/SHA-256。
- 两个产品的 manifest producer 与 verifier 分离；workflow 只调用 owner-local 公共任务。

验证入口是 `pnpm test:tooling`、`deploy/personal-server/tests/test-host-transaction.sh`、
`products/personal-server/scripts/test-release.sh` 和 owner package test/typecheck。
