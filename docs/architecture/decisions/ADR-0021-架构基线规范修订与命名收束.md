# ADR-0021：架构基线规范修订与命名收束

> 目标版本选择已由 [ADR-0023](./ADR-0023-最终目标蓝图与物理目录契约.md) 替代；本文保留当时决策及仍有效的迁移/命名纪律。

- 状态：accepted
- 日期：2026-09-19

## Context

用户明确要求优化冻结基线后采用其中的架构与重构规范，重点包括命名。
原文的 ModelRuntime 示例、Store 持久性含义、第三方包禁令、根树范围和 wire/domain 描述
存在歧义；旧命名指南的 Avatar 目标及无条件删除 alias 与渐进迁移要求不一致。

## Decision

采用 [v2.0 规范修订 1](../../history/architecture-v2.0/Glimmer_Cradle_Architecture_Baseline_v2.0_Frozen.md)。
五个目标根、七个 Core 模块、状态 owner 和依赖方向保持原决策。
命名操作细则由 [命名规范](../../guides/development/命名规范.md) 唯一维护。
本决策替代 ADR-0019 中“原文不作修改”的限制，仅授权本次有记录的规范修订；
原始输入保存在 Git 提交 `cbb6c853`，执行提示词原文保持不变。

基线正文携带修订号，锁标识更新为 `glimmer-cradle-architecture-v2.0-r1`，
同时更新正文 SHA-256 与门禁预期。此修订号只标识架构文档，不改变产品开发版本。

## Consequences

- Runtime 适用生命周期监督及固定术语；领域概念按 owner 命名。
- 旧 Avatar、协议、配置与发布名称按实际消费者迁移，不进行全仓机械替换。
- 通用依赖库与厂商业务协议区分；领域模型与 wire DTO 区分。
- 根树不授权删除工程元数据和用户数据；临时兼容层必须具有退出条件。
- 哈希门禁只检测固定文件变化，无法自动证明职责正确或用户授权；后者须由 ADR、审查及迁移证据确认。

## Alternatives considered

保留冲突原文并增加平行词表会使执行者继续面对两套规则。重设顶层架构超出本次规范优化范围。
