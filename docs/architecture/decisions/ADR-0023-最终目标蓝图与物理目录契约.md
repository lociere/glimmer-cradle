# ADR-0023 最终目标蓝图与物理目录契约

- 状态：accepted
- 日期：2026-09-21
- 授权依据：用户采纳重新评估方案，要求补齐最终蓝图与所有文件，并明确“第三方”不是强制 Extension 的分类条件。
- 范围：目标设计和文档/校验机制；本 ADR 不表示产品实现已经迁移。
- 替代：ADR-0019 的目标版本选择；ADR-0021 的 v2.0-r1 版本绑定；旧目标中 apps/server 与不完整物理树。
- 保持：ADR-0020/0022 单写者、资产恢复与 Conversation Log 边界；ADR-0021 命名和兼容纪律。

## 背景

v2.0 已规定七个 Core owner，但未穷举包内源码、测试、构建、模板、数据和制品文件。
前序评估补充交互/投递、知识生命周期、规划与认知状态、执行 journal 和 authority；这些不能继续只存在于聊天说明。
将第三方身份直接等同 Extension 也不准确：数据库/传输库和产品宿主技术可以是私有实现依赖。

## 决策

采用 [v2.1 蓝图](../blueprint/Glimmer_Cradle_Architecture_Baseline_v2.1_Frozen.md)、
[物理目录规范](../blueprint/Glimmer_Cradle_Target_Physical_Layout_v2.1.md) 与机器清单作为联合目标。
保持七 Core 模块和五语义根，明确 tools/configs/工程元数据等必要非业务根；不为外观删除用户数据。
Apps 收束为 host、desktop、cognition-worker、extension-host，Host 复用本地/headless 业务装配。
Conversation 的 Python 单写者继续由 Cognition Worker 装配；Embodiment 权威语义在 Host 的 TS 模块，既有 C# 行为须等价迁移。

核心保持环境中立。可选渠道、模型、语音、Renderer 与 MCP 接入因独立分发、替换和生命周期需求采用 Extension；
存储驱动、传输库、Electron/OS API 归对应私有 adapter 或 App。不存在“任何第三方依赖都得写扩展”的规则。
扩展仓库位置与扩展契约是两个问题；本目标采用独立接入项目，但不是宣称同仓扩展天然违规。

精确源文件清单独立于动态输出规则；目录树从清单生成。迁移门检查规格同步，最终门比较实物缺项与多项。
目录文件级调整可在已授权切片同步维护；边界变更仍需明确决策和 ADR。锁定摘要不能被误解为静态测试证明授权。

## 备选与取舍

仅补示意树无法检查遗漏；把当前源码树照抄为目标会保留旧 owner；预先创建所有空文件会制造假完成。
因此先固定逐文件目标，不创建产品骨架。细粒度清单增加维护成本，但能发现未同步的文件和遗漏的构建/恢复链路。
冻结是受控演进，不是禁止合理新增测试或拆文件。
Language/进程收束有迁移成本；必须保留 C#/Unity/native、公开 SDK 和历史数据行为证据。

## 成熟项目依据与适用边界

- [VS Code 源码组织](https://github.com/microsoft/vscode/wiki/Source-Code-Organization) 同时有分层 Core、运行环境适配和内置扩展；说明“依赖第三方技术”与“扩展能力”不是同一分类。
- [Home Assistant 集成架构](https://developers.home-assistant.io/docs/architecture_components/) 区分稳定设备领域和外部服务接入；本项目借鉴语义归一，不复制其同仓部署方式。
- [VS Code Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host) 为独立加载承载提供参考；安全等级仍由本项目实际权限机制验证。

以上资料于 2026-09-21 核对。用户此前聊天强调 vendor-neutral Core、公开 SDK 与 composition root；本次明确修正优先于聊天中“所有第三方唯一入口”等绝对化表述。

## 迁移与验证

旧 v2.0 文件归 History，活跃入口切换 v2.1；不改写旧阶段证据。
清单、展示树、锁、架构门、执行记录和迁移地图同一候选更新。
本次验证文档/编码、清单与摘要同步、校验器反例测试及根 typecheck/build。
最终物理核对在当前迁移树上预期失败；产品最终验收按蓝图和执行要求另行完成。
