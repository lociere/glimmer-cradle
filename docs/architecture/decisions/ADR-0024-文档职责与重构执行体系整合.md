# ADR-0024 文档职责与重构执行体系整合

- 状态：accepted
- 日期：2026-10-09
- 授权依据：用户要求整体重构 docs、整合当前重构任务并细化可直接执行的流程。
- 范围：信息架构、物理文档路径、文档工具与重构工作流；产品语义仍为 v2.1。
- 部分替代：ADR-0023 中规范文件的物理路径；保留其领域、状态、协议、数据和 Extension 边界。

## 背景

蓝图目录混入任务操作，Current 持有迁移动作，now 与 2,500 多行执行记录并存且状态不同步。
版本化长文件名使正式文档看起来像外置输入，Codex 无法从旧“下一步”中可靠选择当前任务。

## 决策

采用[文档架构](../../governance/documentation-architecture.md)的职责与精确布局：
目标使用 architecture/target 稳定入口；治理规则进入 governance；通用步骤进入 guides；
长期重构进入 roadmap/initiatives/architecture-v2；已完成里程碑进入 history。
执行状态由 execution.json 唯一拥有，status.md 自动生成；阶段计划、验收矩阵和切片契约分别拥有不同信息。

迁移保留完整原始执行证据，提取当前有效差距，不覆盖或重写历史测试结论。
先完成可读、可验证的接手任务，再细化依赖该调查的实现路径；计划不假定未来 API 已存在。
受控目标锁继续覆盖蓝图、完整路径和规则；加入本决策、执行流程与验收要求，
任务状态及证据不纳入冻结摘要，避免每次记录进度都重新冻结语义。
目录清单仍精确登记状态、证据和历史文件的路径。

## 后果

一次变更只更新各自权威页及链接，减少多份状态与规则漂移。
文档移动涉及相对链接、Skill、工具路径、清单和摘要的原子更新，增加本次迁移工作量。
生成视图检查只能证明一致性；历史证据接受、业务行为与独立审查仍需要实际判断。

## 备选

只添加导航不能解决混合职责与过期状态；全部照搬 Diátaxis 会把内部治理与任务记录强塞进用户文档类型；
机械重命名所有专业指南没有足够收益。本次保留已有有效专业正文，迁移错位职责、重写统一入口。

## 验证

链接与可达性、docs 精确清单、任务依赖/状态、生成视图、锁与目标树、
仓库检查反例、编码、根 typecheck/build；产品行为与生产状态不因本次文档重组获得新验收结论。
来源及适配界限见[文档架构](../../governance/documentation-architecture.md#设计依据)。
