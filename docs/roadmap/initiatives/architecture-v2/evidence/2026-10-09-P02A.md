## 生命周期第一段与时钟/身份 owner

原 LifecycleCoordinator.stopStarted 遇到 stop/observer 异常即跳过后续释放，却 finally
清空整个 started 栈；启动尚在 await 时，stop 还可能清空后由回调重新登记资源。
通用监督实现已移至 `core/platform/src/lifecycle/supervisor.ts`，契约独立至
`runtime-module.ts`，旧 aggregate 源删除，公开 lifecycle export 更新，真实 Kernel
LifecycleOrchestrator 直接消费公开 API。

模块在 start 调用前进入 owned，成功后进入 started；部分启动失败仍由 stop 释放。
关闭立即 fencing 新阶段/模块，排空已接纳启动和 observer 回调后按接纳逆序释放。
stop/observer 失败汇总上抛，不跳过其他资源；成功释放 owner 当即移除，失败 owner 保留
供再次 stop 重试。并发 stop 共享同一排空 Promise，关闭 coordinator 永不重新启动。

真实 App 合并并发 start/stop，回调调用前安装共享 Promise，立即 fencing coordinator；
事件异常仍继续释放；全部资源释放后才关闭总线与 diagnostics，失败期间保留 observer。
失败 owner 不丢失，未释放资源时不发送 AppStopped，状态 ERROR；恢复后
重试仅释放剩余 owner。启动/停止竞态不开放 ingress 或写回 RUNNING。装配时已打开、
未进入 start 接纳的 Application 资源由 App field 持续持有到成功释放；已接纳部分启动由 coordinator
独占释放，避免两次关闭 journal。provider stop 失败时保留其依赖资源；成功停止的
provider/resource 从重试集合移除，Execution 已成功 drain 也不重做；关闭 App 不允许
在已 shutdown 的单例总线上重启，需新的承载。

Clock/ScheduledTask 与 StableIdentity 契约分别落位 `time/clock.ts`、`identity/identity.ts`。
Node 通用实现迁至 `time/system-clock.ts`、`identity/stable-identity.ts`，公开 root 导出
SystemClock/NodeStableIdentity。实际 Kernel composition 及其原 adapter 测试消费者改用
公开 API，原 Kernel 两个机制源删除；原 SHA-256/unit-separator digest 语义不变。

## 回调自等待第二段

`LifecycleCallbackGuard` 使用每实例独立的异步上下文活跃 token，在 module start/stop
和 observer 返回 Promise 未收敛时拒绝其重入所属 start/stop，错误明确指出自等待。
外部并发调用仍加入原 Promise；同步回调返回立即 inactive，异步回调 settle 后
inactive，后续异步 descendant 可正常 stop。其他 coordinator 的 start/stop 独立允许，
不建立跨 owner 的全局禁入。App 的产品事件、ingress关闭、资源释放等回调同样消费
该公开机制，并核验所属 coordinator 的回调上下文；start失败仍通过外部catch释放。

这修正第一段允许同步回调重入共享 Promise 的狭窄语义：同一回调若随后 await 该
Promise，会等待包含自己在内的启动/停机过程，无法释放。现改为明确拒绝此重入，
保留外部并发加入。原重入测试替换为真实 await 自等待拒绝、全部释放继续的反例，
未将自等待伪造为成功或通过提前完成 Promise 绕过真实启动屏障。
