## 实际 catalog 与受控状态子链

复用现有 Memory/Planning 源 outbox、Job source receipt、attempt/lease、对账与状态 inbox。
JobController catalog 从实际注册生成；停止拒绝注册，撤销注册不把已开始副作用声明回滚。
限定 kind 的 Scheduler 在 claim 前和接纳 await 后复验注册，注册缺失保持原 queued/attempt。
listProjection 从唯一 SQL 按精确 scope 与稳定 ID 分页，只公开保留中的状态元数据和真实
outbox 待反馈标志；不含 payload/result、lease owner 或证据正文。

三个 Host owner 逐层暴露受 live lease/epoch 围栏保护的私有 projection port；公开控制路由只
消费生成 DTO，复验可信 Principal、metadata generation、当前 epoch 精确 scope grant，读取后
再次检查撤权/换主/取消。没有创建另一状态 writer，产品 HTTP/UI 装配仍归 P12B。

## Memory 逐任务接纳子链

输入为逻辑提交 `7310ae4e` 后本任务 dirty。唯一 Memory owner 从已 ACK 原源读取 request/job/scope，
核验当前完整 Episode/version/digest、域、enabled/salience 与模型装配；新的只读 RPC 不写库、
不建 attempt/封口或调用模型，受实际 generation/readiness/cancel/drain 约束。Host 在原 Jobs
claim 前接纳，等待保持原 due/预算/identity。原持久 receipt 可恢复而无需新模型。

执行者自查发现生产 factory 总有非空 LLMEngine，故只检查对象存在不足。现在 App 从同一实际
默认 generate 配置注入中立 callback，Core 不读取 provider/secret 或访问网络。模型配置检查
只证明本地配置完整，不宣称供应商健康；原 generate 路由语义未改变。

独立只读审查发现必要 P2：原证据永久失配会被当作普通等待并永久 degraded。修复为 Host 明确
失败关闭循环和 client，保留原 Job/source ACK/receipt，不自动清除不可再生事实或换 ID 重投。
恢复原事实并重启新 epoch 后原 Job 可执行一次；完整修复/备份入口仍归 P13A/P14A。
独立复核已关闭该 P2，本 Memory 子链无剩余阻塞；不接受整个 P07B。
