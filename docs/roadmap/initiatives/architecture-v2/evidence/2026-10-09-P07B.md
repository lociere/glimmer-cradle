## 分页上界与 retention 原恢复引用子链

输入为 `a7463fb7` 后本任务 dirty，唯一 writer 仍为本会话。原 admission 扫描只在短页
回绕；持续新高 ID 会延长一轮，已等待的低 ID 不能重扫。Jobs 现行 schema 4 保持不变：
Store 在当前 authority 下按实际 due 条件读取最大 ID，上界跨 tick 保存在 Scheduler，
后续页限制 `(cursor, boundary]`，短页/空页或满页恰好到界回绕；注销 handler 的所有重置
分支同步清空 boundary。接纳 await 外事务、候选 revision CAS、原 due/attempt/预算不变。

上界不是成员快照：区间内新任务仍可延长扫描。只读审查提出通用任意长 ID 可构造
`a < a0 < a00 < … < b` 的持续插入反例；真实 Memory/Planning 使用固定 hash 身份，但
不能以此关闭通用 Jobs 的公平性门。该剩余保留在 nextAction，继续解决，未降低原验收目标。

实际 Host/Worker/Jobs/Planning/Delivery 隔离链新增 pruned-restart：Jobs 状态完成真实源
inbox/ACK 后 prune 大记录，保留原 source receipt/tombstone/attempt；Jobs 与 Worker
重开，原源按改变的 max-attempts 政策重投仍返回原 tombstone/null，无新 claim；原通知
Prepare/Reply/Turn 恢复一致，实际送达回执后确认原通知，撤销再重启确认幂等且仅一帧。

## 通用接纳顺序与 v4 离线复制迁移子链

输入 `f20aac84` + 本子链 dirty。上一子链已记录的任意 ID 区间持续插入限制由持久单调接纳
序号解决：Jobs singleton highwater 与 enqueue/source receipt/outbox 共用 IMMEDIATE 事务；
duplicate/冲突不分配序号，任一写入失败全部回滚。counter 不随 retention 下降，耗尽安全
整数范围时失败关闭；序号不作为 Job 身份、revision、authority 或对账依据。Job decode 移除
序号，公开 projection/状态事件不包含它；v5 未知 Job 列和损坏窗口拒绝打开。

Scheduler 用私有 `listDueScan` 按序号分页，每轮固定当前 due 最大序号。任何随后接纳项必定
超过上界，任意 ID 长度/顺序、同钟、墙钟回退或 SQLite ROWID 复用都不能扩大这轮；有限旧
窗口达到边界/短空页即回绕，原等待工作可再次接纳。旧已存在且刚到期的项也只属于有限
窗口，不用无界内存快照。`listDue` 仍按 Job ID 为诊断/等待数读取；实际 claim 继续原 ID/
revision CAS。所有源/trigger/事件物化复用原 enqueue 唯一分配路径。

fresh schema v5 与迁移后的 v5 表约束一致。普通打开明确拒绝 v4，不隐式迁移旧用户库。
`copyJobStoreForAdmissionOrderMigration` 仅生成独立候选：只读原 v4，wx 排他占用新目标，
