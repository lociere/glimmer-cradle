`shared/ui/HealthBadge/` 保存当前跨页面组件、CSS Module 与 story。其他表单、列表和 Drawer 直接组合 React Aria/native 元素，领域复合组件保留在对应 feature；不为尚未出现的复用创建空目录。Storybook 从真实组件与 stories 生成文档/manifest，构建输出位于 `build/storybook/personal-server/`，不进入 Git。

目录中的具体 feature 内部文件可按领域复杂度拆分，但不得改变 owner：route 只装配，feature 持有领域 view model/hooks/表单/局部状态，`shared/ui` 只持有无领域事实的可访问原语，`shared/api` 是唯一浏览器跨边界 client/decode 入口。

## 2. Owner 与消费边界

| 物理位置 | Owner | 允许 | 禁止 |
|---|---|---|---|
| `app/router.tsx` | route owner | React Router、URL、history、deep-link、进入/离开和未知路由 | 领域状态机、配置判断 |
| `shell/` | Product Shell | 单层全局导航、当前位置、健康状态、全局操作、响应式 chrome | 复制 feature、常驻空 Context Inspector |
| `routes/` | page owner | 组合 feature 与页面级容量 | 复制 feature 状态、直接访问 Kernel/文件 |
| `features/` | 领域 owner | view model/hooks、表单、异步状态、局部样式和 cleanup | 建立第二套 token/API client、把服务端事实复制进 React state |
| `shared/ui/` | UI primitive owner | React Aria/native semantic primitive、焦点、Overlay、表单和列表/详情原语 | Provider/runtime/Extension 等领域事实、组件库默认皮肤 |
| `shared/styles/` | token/style owner | CSS variables、global、motion、responsive 规则 | 单页业务样式、无 owner 任意值、Tailwind 第二主题 |
| `.storybook/` 与 stories | component workshop owner | 组件发现、状态预览、组件交互/a11y 测试；试点获准时生成 MCP manifest | 模拟 Product Host 端到端事实、替代 Playwright、让 MCP 成为单点依赖 |
| `tests/ui/scenarios/` | UI test fixture owner | 稳定复现公开投影与网络状态 | 成为运行时数据事实源、包含 Secret |
| `visual.spec.ts-snapshots/` | Playwright baseline owner | 固定环境下的代表页面/状态图像证据 | 用批量更新掩盖未知视觉变化 |

## 3. Current → Target 动作

下表保留迁移决策与删除门；Shell/Router、五个页面、七个设置子区及测试拆分已完成，具体证据见下文。品牌资产仍属于独立的未来任务。

| 当前 | 动作 | 目标/删除门 |
|---|---|---|
| `main.ts` + `bootstrap.ts` 命令式 DOM 启动 | replace | `bootstrap.tsx` 使用单一 React root；所有页面迁移、E2E 通过后删除旧启动路径 |
| `shell/layout.ts` 通过 `innerHTML` 同时生成 Shell、导航、所有页面挂载点和常驻 Inspector | replace | 迁为 `PersonalServerShell.tsx`；route 迁移并通过导航/焦点测试后删除旧文件，不保留双 Shell |
| 内存 `AppRouter` | replace | React Router 浏览器路由成为正式 URL/history/deep-link 语义；Product Host index fallback、未知路由、刷新、back/forward 通过后删除旧入口 |
| feature 直接创建/查询/修改 DOM | migrate/delete | 每个 feature 按垂直 slice 迁为 React component + hook/view model；consumer 全迁后删除旧 DOM helper/listener，不保留 wrapper 壳 |
| `status`、`extensions`、`observability` 与单页 `configuration` 命名/装配 | reshape | 收敛到概览、能力、活动、设置一级域；旧 data-route、旧标题映射和重复导航零运行时残留 |
| 所有复杂 view 同时挂载 | replace | 当前 route 唯一参与布局与可访问交互；页面离开 effect cleanup 有测试，旧常驻挂载删除 |
| 常驻 `.inspector` | delete/replace | 选中真实对象时才创建 Context Drawer；未选对象、关闭、Escape、scrim 和焦点返回通过 |
| 单一 `tokens.css` + 大量 feature 任意值 | reshape | 语义 token 覆盖 typography/spacing/radius/surface/control/focus；CSS Modules 按 owner 持有局部样式，motion/responsive 分离 |
| 文字 `G` 与单字伪图标 | delete | 由未来 canonical 品牌/图标入口替换；在正式入口未就绪前不得把另一组临时字符写成目标实现 |
| 无组件工作台与真实 API manifest | create | Shared UI 和代表复合组件具备 stories、生成文档和本地组件测试；Storybook MCP 仅在试点证明收益时提供额外发现入口 |
| 单个 `control-surface.spec.ts` 承担大部分 UI 回归 | split/retain evidence | 按 navigation/state/accessibility/visual 拆分；既有功能场景迁移后删除重复断言，不降低覆盖 |
| 仅 failure screenshot | extend | 建立代表页面/关键状态基线；固定字体、viewport、动画和数据，基线更新需人工审查 |

迁移按 Shell/Router → shared UI → 对话/概览代表 slice → 能力/活动 → 设置子域推进。每个 slice 迁移真实 route、状态和测试后立即删除对应旧 DOM owner；允许迁移分批提交，不允许最终发行物同时保留两套主线或按页面长期双栈。

### Shell/Router、概览与对话 slice 的当前证据

- `main.tsx`、`bootstrap.tsx`、`router.tsx` 与 `PersonalServerShell.tsx` 已成为唯一 React root、认证装配、route table 与 Product Shell；被替代的 `.ts` 启动、内存 Router 和 `shell/layout.ts` 已删除。
- `/conversation`、`/overview`、`/capabilities`、`/activity`、`/settings`、根路径与 unknown route 由 BrowserRouter 和 Product Host fallback 共同成立；fallback 仅接受安全 `GET` HTML 导航，静态资源 `GET/HEAD`、API/保留前缀、asset miss、其他 method 与 traversal 均 fail closed；当前 route 唯一挂载，离开时 feature effect cleanup。
- 首批 semantic token、深浅主题、480×900 壳层、`HealthBadge` story 与概览截图基线已落地；Storybook MCP 未启用。
- 概览已从 route adapter 迁为 `Overview` / `useOverview` / `RuntimeDetails`，旧 `features/status/status-view.ts`、`status.css`、`mountOverview` 及共享 status 样式覆盖已删除，架构测试防止旧入口回流；当前装配与投影语义见 [Product Compositions](../../reference/product-compositions.md)。

## 4. AI 可消费上下文

AI 按以下优先级发现 UI：

1. Storybook 由真实 stories 生成的组件文档和本地可浏览状态；若 MCP 试点启用，再消费同源 manifest；
2. `shared/ui/` 的公开 props、类型、实现和 CSS Module；
3. route/feature 的直接 consumer；
4. `tests/ui/scenarios/` 的可复现状态与 Playwright 断言；
5. `shared/styles/tokens.css` 与 [UI Design Tokens Reference](../../reference/ui-design-tokens.md) 的语义说明。

Storybook manifest 是从实现生成的投影，不是第二事实源。若未来采用 DTCG token 生成链，必须由 canonical token source 生成 CSS；不得让 JSON、CSS 和 Storybook theme 三处手写同一值。

## 5. 验收与删除门

- 架构：ADR-0017 保持 `accepted`；实施 slice 固定 React/Vite/Router/React Aria/Storybook 的版本和直接 consumer，旧 DOM 主线有逐 slice 删除证据。
- 目录：`routes/`、`shared/ui/`、stories、状态 scenarios 和视觉基线真实存在，`product-compositions.md` 与实际路径一致。
- 正确性：目标页面唯一可见；登录层隔离；URL/history/deep-link/refresh/back/forward/unknown route 通过。
- 状态：代表页面覆盖 default/loading/empty/degraded/error/pending/success，写操作覆盖脏状态、冲突和失败恢复。
- 容量：宽屏、临界宽度、窄屏、长内容、100–400% 缩放无非预期横向溢出，主要任务区不被重复 chrome 挤压。
- 交互：键盘、focus-visible、Overlay/Drawer、Escape、scrim、焦点返回、触控目标和 reduced-motion 通过。
- 组件：AI 与人可从 stories、生成文档、类型和本地 test runner 发现真实 shared UI API、预览代表状态并运行组件/a11y 测试；MCP 试点必须有固定版本、fallback、收益指标和删除条件，关闭后不影响该闭环。
- 视觉：按 [M11 UI 设计简报](../design-briefs/M11-Personal%20Server%20UI设计简报.md) 完成用户确认；最终方向的对话、概览、设置和关键状态截图经人工审查后固定。
- 删除：旧 `innerHTML` Shell、DOM query/mutation 页面主线、重复导航、常驻 Inspector、单字伪图标、旧 route 值和被替代任意样式无运行时残留。
- 工程：Storybook build/组件测试、Personal Server 定向测试、typecheck、Vite build、Playwright 通过；若改变跨产品共享层或 Desktop，再补对应产品门。
