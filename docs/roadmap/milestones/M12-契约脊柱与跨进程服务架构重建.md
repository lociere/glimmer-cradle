## 目标成果

用户已显式要求在 M11 未完成时继续完成 M12；该授权只改变推进顺序，不改变 M11 状态或 M12 边界。M12 目标是把当前万能 `protocol/` 重建为 `contracts/` 契约脊柱：跨进程可调用能力使用版本化 Protobuf Service，核心器官默认通过受 Kernel 监督的 gRPC 协作，Web/Desktop Surface 只访问 Kernel Surface Gateway，配置与 package 等文档型契约继续由 JSON Schema 拥有。

Slice 1 `contracts baseline` 已集成。Slice 2 已迁移 Kernel↔Cognition v1 Service、gRPC host/client、动态回环端点、generation/PID 注册、readiness 与重启/停机链，并删除该边界旧 ZMQ/envelope、配置、生成物和 package dependency。该事实不表示 M11 已完成，也不表示其余 `protocol/` 已可删除。

完成后，TypeScript、Python 与 C# 边界拥有同一份可生成、可兼容检查的 Service 定义；Command、Query、Event、Stream、Document 语义分离；错误、deadline、cancellation、trace、causation/correlation 和 readiness 可验证；ZMQ 自制 RPC、stdio 命令协议和被替代的手写 WebSocket 主线已按边界删除，不存在无退出条件双轨。

同一里程碑还把目标物理职责落到真实仓库：`core/`、`engines/`、`hosts/`、`products/`、`packages/`、`contracts/`、`native/`、`templates/` 边界可由 imports、composition root、构建、测试和打包证明；Kernel 与 Cognition 收口为各自模块化单体；Avatar 领域与 UnityAvatarHost 分离；Extension Host 成为 Kernel 监督的独立不可信代码崩溃域。当前目录在迁移完成前仍由 Current/Implementation 如实描述。

整个 milestone 与 Slice 1–9 的完成态目录、Current → Target 动作和旧 consumer 删除门
见 [M12 完成态物理目录](../manifests/M12-目标物理清单.md)；本页只保留成果、顺序、
风险和验收语义。M12-9 的冻结 inventory 只作迁移起点，候选删除必须重新核对源码、
构建、package dependency、dependency artifact、generated mirror、validator 与 fixture。

## 范围

- 建立 `contracts/proto/`、`contracts/json-schema/`、Buf 配置、兼容基线和可复现生成链。
- 固定 `common`、Kernel、Cognition、Surface、Avatar、Audio Engine、Extension Host 的 Service owner、依赖方向和 `v1` package。
- 建立领域模型 ↔ generated DTO 的边界 Adapter；禁止业务层依赖生成 stub。
- 迁移 Kernel ↔ Cognition、Kernel ↔ Engine/Avatar/Extension Host 和 Surface ↔ Kernel Gateway 主线。
- 建立 typed error、deadline、cancellation、metadata、trace、causation/correlation、readiness 和 generation 校验。
- 建立 control/data plane；为媒体与 Blob 固定 stream/reference/lease 策略和阈值。
- 建立 Buf breaking、JSON Schema compatibility、TS/Python/C# round-trip、Adapter contract test 和受影响 E2E 门。
- 建立目标根职责树、专属 owner 优先级与依赖方向门；保留 `templates/extension-basic/` 的开发模板职责，新增 `hosts/` 只承载没有更专属 owner 的具体承载/不可信崩溃域。
- 将 Kernel 收口为 `domain/application/ports/adapters/runtime/composition`，删除泛化 `foundation/`、无 owner 的 `application/services/` 和 transport 对业务层的侵入。
- 将 Cognition 收口为 `domain/application/ports/adapters/host`，保持单一心智进程与一致性边界，删除领域/技术平级旧入口和心智包内部的 `protocol/generated/`。
- 建立可独立 `dotnet build` / `dotnet test` 的 Core Avatar C# assembly，并由 `hosts/` 下 UnityAvatarHost 单向消费；将执行第三方代码的 Extension Host 从 Kernel 内迁到 `hosts/` 独立进程。
- 为同进程 Application 事务与跨进程 Saga/Process Manager 建立边界、幂等、补偿、causation/correlation 和失败终态测试。
- 对 `packages/` 建立统一准入门：公开 SDK，或至少两个真实产品 owner 的稳定跨产品消费者，并同时具备独立 API、版本/兼容策略、测试和明确 owner；不预建 UI shared package。
- 在每个迁移切片通过验收后删除对应旧入口、旧生成链、兼容桥和 feature flag；最终删除 `protocol/`。
- 同步 Current、Implementation、Reference、Guide、SDK 与打包事实源，使目标物理形态和真实代码一致。

## 非范围

- 不改变 Cognition、Kernel、Avatar、Engine 或 Extension 的领域主权。
- 不把远程公网 API、托管云、多租户或第三方开放 API 混入本地器官 Service。
- 不用 Protobuf 取代配置、Character Package、Extension manifest/package 或动态 Skill/tool 参数的 JSON Schema。
- 不让 Surface 直连 Cognition、Engine、Avatar 或 Extension 内部服务。
- 不因迁移重写业务功能、人格、记忆、Avatar 行为或模型算法。
- 不把 Cognition 的 identity/persona/affect/experience/memory/conversation/context/deliberation/volition 拆成网络服务或独立一致性边界。
- 不把 Kernel 拆成微服务，不把第三方扩展业务逻辑迁入 Kernel Domain/Application。
- 不引入跨器官分布式数据库事务，也不用万能 Event Bus 或 generated DTO 代替明确的本地 use case 与跨进程 Saga。
- 不为预期复用创建 UI shared package；不满足“公开 SDK，或至少两个真实产品 owner 稳定消费”且同时具备独立 API、版本/兼容策略、测试和明确 owner 时，不进入 `packages/`。
- 不在本里程碑之外重排 configs/assets/data/deploy/scripts/docs 等已有明确职责根。
- Root `scripts/`、`deploy/` 与工程文档的 owner-local 任务重排、CI/Build/Release/Install/Ops 生命周期收口明确 deferred 给 [M13](./M13-工程自动化脊柱与交付生命周期闭环.md)；M12 只修改其自身切片不可避免的生成、构建、打包消费者，不扩大 contracts baseline 或九个切片的验收范围。
- 不长期保留 ZMQ/gRPC、stdio/gRPC 或手写 WebSocket/Connect 两条等价主线。
- 不在无实测证据时固定 shared memory、Connect streaming 或平台认证的具体实现。
- 不把 Audio 独立进程移出 `engines/`，不把 Desktop/Personal Server 入口移出 `products/`，不把 Cognition 唯一入口移出 `core/cognition/host/`。
- 不把 Core Avatar 继续编译在 Unity asmdef 中，不复制 Avatar Domain 源码，也不把外部 NuGet/云 registry 变成唯一交付来源。
- 不要求同一切片同时修改 transport 与 Kernel/Cognition 全量内部结构，不以整个 M12 的大爆炸式验证代替逐切片 fixed state。

## 实施阶段与旧入口删除条件

M12 是一个 umbrella milestone，不新建平行总里程碑。下面九个切片按顺序独立固定、独立审查、独立关闭；每个切片只消费前一切片的输出 fixed state。任一切片失败即停止后续，不扩大为全 M12 大爆炸验证，也不要求 transport 切片同时完成 Kernel/Cognition 全量内部重构。

### Slice 1：contracts baseline

- **Owner**：Contract Spine owner。
- **输入 fixed state**：用户授权 M11 暂停但未完成时先做本切片；ADR-0013/0014 accepted；当前 `protocol/` 与生成链 inventory 已冻结。
- **旧路径/consumer inventory**：`protocol/src/schemas/`、TS/Python/C# 生成物、配置/SDK consumers、Buf/validator 与构建入口。
- **必跑门**：三语言最小 Service/Document、Buf lint/breaking、JSON Schema dialect/fixture/compatibility、round-trip、离线可复现生成和供应链摘要。
- **回退窗口**：本切片不切运行主线；工具链 spike 未过即撤销未采用骨架并记录阻断。
- **删除条件**：只删除被新 baseline 明确替代且无 consumer 的试验脚手架；不提前删除运行中的 `protocol/`。
- **输出 fixed state**：唯一 canonical `contracts/` baseline、固定生成链和兼容基线 commit。

Slice 1 baseline 已集成到 `contracts/`：

- `contracts/proto/glimmer/common/v1/contract_probe.proto` 是 Protobuf Service 最小基线。
- `contracts/json-schema/skill/v1/tool-parameters.schema.json` 是 JSON Schema Document 最小基线。
- `contracts/generated/ts/`、`contracts/generated/python/` 与
  `contracts/generated/csharp/` 是 Buf 生成物，只属于 Adapter/Transport 边缘。
- `contracts/compatibility/proto-image.binpb` 与 `contracts/compatibility/json-schema-baseline.json` 是仓库内兼容基线，不依赖 BSR。
- `contracts/inventory.md` 冻结旧 `protocol/` schema、生成物、配置/SDK consumer、validator/build/package 入口、owner、迁移切片与删除条件。
- `contracts/supply-chain.md` 记录 Buf、protoc、TS/Python/C# runtime、validator、来源、许可证、摘要/锁定证据和缓存方式。

### Slice 2：Kernel–Cognition transport

> 完成状态：已完成。Kernel↔Cognition 的唯一运行主线为 v1 Protobuf Service + 受 Kernel 监督的动态回环 gRPC；安装态显式携带 Contracts runtime；FD 3 challenge 及全失败路径 capability 清零、Attention 持有的真实感知 operation 终态、贯穿 synthesis 的反向 action deadline/cancellation、稳定 invocation/步骤级 post-commit 幂等、typed manual recovery projection 与 crash/readiness 恢复均已闭合；旧 ZMQ/envelope 主线、生成物、配置、fixture、validator 和包依赖已通过引用归零门。

- **Owner**：Kernel Service/Topology owner；Cognition owner 审批 Adapter 语义。
- **输入 fixed state**：Slice 1 输出 commit；ZMQ/envelope producer-consumer inventory 已冻结。
- **旧路径/consumer inventory**：Kernel ZMQ Router/client、Cognition RPC host、perception/cycle/action/synthesis/heartbeat/shutdown/readiness envelope、配置和测试。
- **必跑门**：成功、typed failure、deadline、cancellation、trace、causation/correlation、generation mismatch、restart/recovery、readiness、幂等/补偿 contract test 与真实启动链。
- **回退窗口**：只在该切片验收前允许有唯一 owner/指标的 ZMQ 回退开关；失败回退后不得进入 Slice 3。
- **删除条件**：新 transport 全门通过且观测稳定后，删除对应 ZMQ 自制 RPC、万能 envelope、旧配置、测试入口和回退开关。
- **输出 fixed state**：只固定 Kernel–Cognition transport 的 clean commit；不夹带 Kernel/Cognition 全量目录重构。

### Slice 3：Kernel layout

> 完成状态：已完成。Kernel 已物理收口到 `domain/application/ports/adapters/runtime/composition`；Ports 统一承接 config、filesystem、process、observability、endpoint 与 readiness facts，composition 是具体实现绑定点，Runtime 不再直接 import Adapter。Domain 使用本地事件词汇，协议/generated 仅留在 Adapter 边界映射。`RuntimeReadinessProjectionMapper` 位于 Application，是 runtime readiness catalog 的唯一 store mutation；真实 import/export/dynamic-import gate 覆盖层矩阵与负向样本。此 slice 没有迁移 Extension Host 独立进程，也没有改变 transport 语义。

- **Owner**：Kernel owner。
- **输入 fixed state**：Slice 2 输出 commit；Kernel import、Projection writer、OS/process side-effect inventory 已冻结。
- **旧路径/consumer inventory**：`foundation/`、`application/services/`、`lifecycle/`、`infrastructure/`、`host/`、composition/import/build/test consumers。
- **必跑门**：`domain <- application -> ports <- adapters` import 断言；Domain 无 OS/process 副作用；Application 启停/重启/恢复 use case；Runtime 世代/readiness/回收；唯一 Application projection mapper/read model；受影响 Kernel typecheck/test/build 与生命周期故障注入。
- **回退窗口**：目录迁移可在本切片分提交回退，但输出 fixed state 前不得保留新旧 import 主线；失败即停止 Slice 4。
- **删除条件**：旧 imports、Projection writer、side-effect owner、配置、测试、构建消费者归零后删除旧聚合目录、re-export 和 feature flag。
- **输出 fixed state**：Kernel `domain/application/ports/adapters/runtime/composition` clean commit，transport 行为不再改变。

### Slice 4：Cognition layout

- **Owner**：Cognition owner。
- **输入 fixed state**：Slice 3 输出 commit；Cognition 模块/import/transaction/generated DTO inventory 已冻结。
- **旧路径/consumer inventory**：平级领域/技术目录、`foundation/`、内部伪 Port、`protocol/generated/`、host/composition、测试和打包 consumers。
- **必跑门**：`domain/application/ports/adapters/host` import 断言；内部模块只经有名称的 Application use case、模块 API、领域事件和本地事务协作；Ports 仅外部边界；跨进程 Saga 幂等/补偿/人工恢复；Cognition 全量测试。

- **输出 fixed state**：可独立构建测试的 `core/avatar/` C# Core 与 `hosts/` UnityAvatarHost clean commit；具体 leaf 同切片按命名规范固定。

### Slice 8：media data plane

- **Owner**：Kernel control-plane owner；对应 Audio/Avatar/Blob data-plane owner 负责资源通道。
- **输入 fixed state**：Slice 7 输出 commit；Audio/Avatar/图像/模型/Blob 大小频率与当前 stdio/WebSocket/内嵌 payload inventory 已冻结。

- **必跑门**：stream/reference/lease/shared-memory 阈值基线、背压、取消、expiry、digest/权限、崩溃清理、长运行、内存/CPU/延迟/吞吐和数据不进入普通消息断言。
- **回退窗口**：每种媒体通道在其验收前可保留一个有 owner/指标/期限的旧通道；任一 required data plane 未过即停止 Slice 9。
- **删除条件**：目标通道与清理门通过后逐边界删除被替代 stdio/WebSocket/内嵌 payload、临时 bridge 和 feature flag。
- **输出 fixed state**：control/data plane 分离及实测阈值 clean commit。

### Slice 9：最终旧路径收口

- **Owner**：M12 milestone owner；各领域 owner 对自己的删除清单签字。
- **输入 fixed state**：Slice 8 输出 commit；前八切片输出 fixed state 与全仓旧路径/consumer inventory 已冻结。
- **旧路径/consumer inventory**：`protocol/`、旧生成物/配置/脚本、ZMQ/stdio/手写 WebSocket、旧 Host/asmdef/聚合目录、re-export、compatibility bridge、feature flag、测试和文档。
- **必跑门**：全仓 import/引用/重复源码扫描；Contracts compatibility 与三语言 round-trip；Kernel/Cognition/Avatar/Extension/Surface/media 全部受影响构建测试；安装、启动、readiness、故障、停机、打包和文档一致性矩阵。
- **回退窗口**：只允许回退到 Slice 8 的完整 fixed commit；不得选择性恢复单个旧主线。失败时停止 M12 关闭。
- **删除条件**：旧引用、迁移指标和所有临时入口归零；Current/Implementation/Reference/Guide 与真实新代码同步；无后台测试进程和临时产物。
- **输出 fixed state**：M12 最终 clean commit；`protocol/` 与所有被替代物理/transport 主线删除，里程碑才可归档。

## 成功、失败、降级与回退

| 情况 | 语义 |
|---|---|
| unary 成功 | 方法承诺已经成立；异步工作只返回 accepted/pending 并提供状态查询 |
| typed 业务失败 | gRPC status + 稳定 detail；调用方按 code 处理，不解析 message |
| deadline / cancellation | 传播到上游并停止工作；已提交副作用按方法幂等/补偿契约解释 |
| required service 未 ready | Kernel 阻止对应 Ingress，不排入黑洞 |
| optional organ degraded | 撤销能力并更新 Projection；不伪装完整 ready |
| stream/data reference 失败 | 控制面显示失败/过期/取消；清理 lease 和临时资源 |
| 新链路切换失败 | 只在该切片明确回退窗口内恢复旧主线并保留诊断；修复后重新过门 |
| 平台级阻断 | 停止切片，由新 ADR 修改已接受方向；不得永久停在双轨 |
| 同进程事务失败 | 由本地事务边界回滚或进入明确失败终态；不发送伪成功跨域事件 |
| 跨进程 Saga 部分成功 | Process Manager 记录步骤，按契约补偿或进入可查询人工恢复态；不宣称分布式原子成功 |

## 风险

| 风险 | 应对 |
|---|---|
| Protobuf DTO 污染领域层 | import 边界检查、Adapter contract test、代码审查门 |
| gRPC/Connect 语言插件能力不齐 | 先做三语言/双平台 spike，以固定版本和最小功能矩阵选型 |
| 本地端点被其他进程冒用 | 延续动态 catalog，并验证 owner PID、进程世代与平台认证 |
| Surface Gateway 变成万能业务层 | 只做 BFF/Projection 与受控 command，领域判断返回 owner |
| stream 缺少背压或取消导致内存增长 | 有界队列、flow-control、deadline、取消和长运行指标 |
| 媒体全部走普通 RPC 导致复制和延迟 | control/data plane 分离，基于大小/频率基线决定通道 |
| 双轨迁移长期化 | 每切片先写删除对象、owner、指标和完成门；未删除不得关闭切片 |
| JSON Schema 与 Protobuf 复制同一结构 | 契约归属清单、生成/引用规则和重复定义扫描 |
| 版本号跟随应用版本失控 | `glimmer.*.v1/v2` 与产品 SemVer 分离，Buf breaking 固定基线 |
| 迁移破坏 readiness 或监督权 | ADR-0009 contract test、崩溃/重启/停机矩阵和 Kernel 拓扑断言 |
| 生成与兼容门依赖托管服务 | Schema 全量入库、工具和插件版本固定、离线生成/`buf breaking` 门、供应链许可证与摘要清单 |
| transport/runtime 渗入领域模型 | Domain/Application/Port import 门；替换 gRPC/Connect 的 Adapter contract test 不允许修改领域模型 |
| Cognition 被目录分域误拆成微服务 | 进程/端点/数据 owner 断言；心智模块只通过本地 Application use case、模块 API 和领域事件协作 |
| 物理迁移只改目录外壳 | imports、composition、生成、配置、测试、构建、打包和文档联合删除门 |
| 根职责因“有进程/可复用”再次重叠 | 专属 owner 优先级正负样本：Audio→engines、Desktop/Personal Server→products、Cognition host→core、Unity/Extension Host→hosts、脚手架→templates |
| Avatar 领域继续依附 Unity | 独立 dotnet build/test、禁止 Unity/Cubism/transport import、单向 assembly reference 与复制源码扫描；旧六 asmdef/旧目录删除才关闭切片 |
| Extension 第三方代码回流 Kernel | 进程隔离与 import/装载扫描；Kernel 只保留监督、权限、catalog、编排和 Projection |
| Kernel supervision/Projection 双 owner | Domain policy、Application use case/mapper、Runtime execution/facts 和 Adapter 副作用定向 import/写入扫描 |
| Cognition 为内部模块建立伪 Port | module API/use case/domain event 与外部 Port 分类清单；禁止内部模块 RPC/Port 一对一镜像 |
| `packages/` 或 UI shared 过早抽象 | 公开 SDK 或两个真实产品 owner，且独立 API/兼容策略/测试/owner 四项同时通过 |
| 九切片重新膨胀为大爆炸 | 每个切片独立 input/output fixed state、inventory、gate、rollback、delete 记录；前一切片失败即停止 |

## 验收门

### 架构与物理形态

- `contracts/` 是唯一契约脊柱；Protobuf Service 与 JSON Schema 文档契约职责分明。
- `protocol/`、被替代的 ZMQ/stdio/手写 WebSocket 主线、旧配置、旧生成物和无期限桥接已删除。
- Kernel 是内部服务拓扑和 Surface Gateway owner；不存在器官横向发现/直连或 Surface 直连内部器官。
- 生成 DTO 只存在于 Adapter/transport 边界，领域层 import 门通过。
- gRPC/Connect 只出现在 Adapter/Transport/composition root；以测试替换默认 transport 时不修改领域模型与业务 Port。
- 根职责树由真实目录、package、imports、composition root、生成、配置、测试、构建和打包共同证明；`templates/extension-basic/` 仍是开发脚手架。正负样本固定为 Audio→`engines/`、Desktop/Personal Server→`products/`、Cognition host→`core/`、UnityAvatarHost/Extension Host→`hosts/`、canonical IDL→`contracts/`。
- Kernel 物理收口为 `domain/application/ports/adapters/runtime/composition`；Domain 只持策略/状态机，Application 持启停恢复 use case 与唯一 Projection mapper，Runtime 执行世代/readiness/回收，OS/process 副作用只经 Ports/Adapters；旧聚合与重复 Projection writer 已删除。
- Cognition 仍是一个独立进程和单一一致性边界，并收口为 `domain/application/ports/adapters/host`；内部模块只通过 Application use case、模块 API 和领域事件协作，Ports 只表达外部边界，心智内部不存在伪服务或 `protocol/generated/` 领域模型。
- `core/avatar/` 是 Unity 外可独立构建测试且不依赖 Unity/Cubism/transport/generated DTO 的 C# Core assembly；UnityAvatarHost 位于 `hosts/` 并单向消费该本地 artifact，Host Adapter mapping 通过，旧六 asmdef、`core/avatar/unity-host/`、复制源码和旧构建入口已删除。
- Extension Host 位于 `hosts/` 独立进程；Kernel 不执行第三方 handler，且旧执行入口/Worker 协议/兼容桥已删除。
- `packages/` 中每个包都是公开 SDK，或有至少两个真实产品 owner 的稳定消费者；并同时具备独立 API、版本/兼容策略、测试和明确 owner。generated contract output 遵循 ADR-0013，不因复用自动进入 `packages/`；不存在无真实复用依据的 UI shared package。
- 九个切片各有可追溯 owner、输入/输出 fixed state、inventory、必跑门、回退窗口和删除证据；没有跨切片大爆炸提交。

### 兼容与跨语言

- Buf lint/breaking 对固定基线通过；破坏性变更只通过新世代和迁移计划进入。
- JSON Schema dialect、fixture 与 compatibility 门通过；同一消息无双事实源。
- TypeScript、Python、C# serialization round-trip 和所有 Adapter contract test 通过。
- 应用版本升级与 `v1/v2` 契约世代可以独立演进。
- 固定版本的 Buf/`protoc`/语言插件、JSON Schema validator 和生成链可离线复现；不访问 BSR 或其他专有云也能完成 lint、breaking、generate 和 round-trip。
- canonical `.proto`/JSON Schema 均在仓库，依赖许可证与摘要可审计；远程插件和托管 SDK 不是唯一来源。

### 生命周期与语义

- Command、Query、Event、Stream、Document 均有代表性端到端链路；无 `payload:any` 万能 envelope。
- 成功、typed failure、deadline、cancellation、trace、causation/correlation、readiness、generation mismatch 和幂等/补偿语义均有测试。
- Required/optional service 的 waiting/degraded/failed/restart/stop 投影与 Ingress 行为通过故障注入。
- ADR-0009 的动态回环端点、进程隔离、监督回收和真实 readiness 在 Windows/Linux 通过。
- Cognition/Kernel 同进程 use case 与事务回滚、跨进程 Saga/Process Manager 的幂等、补偿、超时、causation/correlation、查询和人工恢复语义均有故障注入证据。
- Kernel Projection 只有 Application mapper/read model owner；Domain/Runtime facts 输入、重复 writer 和运行时恢复均有定向测试。

### Surface 与数据面

- Desktop/Web 只访问 Kernel Surface Gateway；浏览器认证、权限拒绝、断线、重连、背压、取消和状态矩阵通过。
- Audio/Avatar/Blob 数据面有实测阈值、资源上限、lease/stream 清理和长运行证据；大型数据不进入普通消息。
- 性能基线覆盖启动、首次调用、稳态延迟、吞吐、内存、CPU、包体和多实例。

### 工程与文档

- 受影响 typecheck、build、Python/C# 测试、跨进程集成、Desktop/Personal Server UI、安装和停机矩阵全部通过。
- Avatar Core 独立 `dotnet build` / `dotnet test`、禁止依赖扫描、Host Adapter mapping、Unity Host、Desktop/package build 和本地离线 assembly 打包全部通过。
- Current、Implementation、Reference、Guide、SDK、打包和排障文档与代码一致；不再把目标写成未来，也不保留旧术语主入口。
- 迁移期观测指标归零，所有 feature flag、compatibility bridge、临时端点和测试进程已清理。
