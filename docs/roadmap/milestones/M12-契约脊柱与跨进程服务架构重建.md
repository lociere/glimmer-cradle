## 目标成果

在 M11 完成并退出唯一活跃推进面后，把当前万能 `protocol/` 重建为 `contracts/` 契约脊柱：跨进程可调用能力使用版本化 Protobuf Service，核心器官默认通过受 Kernel 监督的 gRPC 协作，Web/Desktop Surface 只访问 Kernel Surface Gateway，配置与 package 等文档型契约继续由 JSON Schema 拥有。

完成后，TypeScript、Python 与 C# 边界拥有同一份可生成、可兼容检查的 Service 定义；Command、Query、Event、Stream、Document 语义分离；错误、deadline、cancellation、trace、causation/correlation 和 readiness 可验证；ZMQ 自制 RPC、stdio 命令协议和被替代的手写 WebSocket 主线已按边界删除，不存在无退出条件双轨。

## 范围

- 建立 `contracts/proto/`、`contracts/json-schema/`、Buf 配置、兼容基线和可复现生成链。
- 固定 `common`、Kernel、Cognition、Surface、Avatar、Audio Engine、Extension Host 的 Service owner、依赖方向和 `v1` package。
- 建立领域模型 ↔ generated DTO 的边界 Adapter；禁止业务层依赖生成 stub。
- 迁移 Kernel ↔ Cognition、Kernel ↔ Engine/Avatar/Extension Host 和 Surface ↔ Kernel Gateway 主线。
- 建立 typed error、deadline、cancellation、metadata、trace、causation/correlation、readiness 和 generation 校验。
- 建立 control/data plane；为媒体与 Blob 固定 stream/reference/lease 策略和阈值。
- 建立 Buf breaking、JSON Schema compatibility、TS/Python/C# round-trip、Adapter contract test 和受影响 E2E 门。
- 在每个迁移切片通过验收后删除对应旧入口、旧生成链、兼容桥和 feature flag；最终删除 `protocol/`。
- 同步 Current、Implementation、Reference、Guide、SDK 与打包事实源，使目标物理形态和真实代码一致。

## 非范围

- 不改变 Cognition、Kernel、Avatar、Engine 或 Extension 的领域主权。
- 不把远程公网 API、托管云、多租户或第三方开放 API 混入本地器官 Service。
- 不用 Protobuf 取代配置、Character Package、Extension manifest/package 或动态 Skill/tool 参数的 JSON Schema。
- 不让 Surface 直连 Cognition、Engine、Avatar 或 Extension 内部服务。
- 不因迁移重写业务功能、人格、记忆、Avatar 行为或模型算法。
- 不长期保留 ZMQ/gRPC、stdio/gRPC 或手写 WebSocket/Connect 两条等价主线。
- 不在无实测证据时固定 shared memory、Connect streaming 或平台认证的具体实现。

## 依赖

- M11 完成，当前产品控制面、Extension 与发布事实稳定，避免两项跨层迁移同时争夺同一边界。
- ADR-0009 的动态端点 catalog、监督树、进程树回收和 readiness 模型保持有效。
- 受支持 Node/Python/C# 工具链能在 Windows/Linux 生成、构建并运行最小 gRPC/Connect contract test。
- 现有 Schema、producer、consumer、ZMQ/stdio/WebSocket 路径和测试清单完整，可逐边界证明删除。
- 发布与安装链能携带新增生成物和本地服务依赖，并保持可复现与离线安装。
- canonical `.proto`/JSON Schema、固定版本生成器与兼容基线均可从仓库和固定制品取得；Buf Schema Registry、远程插件或其他专有云服务不作为前置条件。

## 实施阶段与旧入口删除条件

### 1. 工具链与兼容基线

建立最小三语言 Service、JSON Schema dialect/fixture、Buf lint/breaking 和 round-trip。只有 Node/Python/C# 在目标平台通过生成与调用、包体/启动开销有基线后，才选择插件并进入生产迁移；失败时记录阻断并通过新 ADR 调整方向，不静默复用旧架构。

### 2. Kernel ↔ Cognition

迁移 perception、cycle/action、synthesis、heartbeat、shutdown 和 readiness。成功、领域失败、deadline、取消、trace、进程重启、generation mismatch 与恢复全部通过后，删除 ZMQ 自制 RPC、对应万能 envelope、旧配置和旧测试入口。

### 3. Kernel ↔ Engine、Avatar 与 Extension Host

按器官逐一迁移，保持 Kernel 单一拓扑 owner。每条链路在资源未就绪、崩溃、重启、降级、主动停机、流中断和进程树回收通过后，删除对应 stdio 命令协议或手写 WebSocket 主线；未通过的边界不得宣告完成。

### 4. Surface Gateway

Desktop/Web 只通过 Kernel Surface Gateway 读取 Projection 和提交受控 intent。Connect unary/streaming 与 WebSocket 的最终分工以浏览器兼容、背压、取消、认证和实测延迟决定。目标链路通过 deep-link 会话恢复、断线重连、权限拒绝、状态矩阵和关键交互回归后，删除被替代的手写 Surface WebSocket 主线。

### 5. 数据面与物理收口

按实测阈值为 Audio、Avatar、图像、模型和 Blob 固定 streaming、lease/reference 或 shared memory；验证 expiry、取消、清理、背压和进程崩溃。所有包、脚本、配置、生成物、测试和文档停止引用 `protocol/` 后删除旧目录、迁移桥和 feature flag。

## 成功、失败、降级与回退

| 情况 | 语义 |
|---|---|
| unary 成功 | 方法承诺已经成立；异步工作只返回 accepted/pending 并提供状态查询 |
| typed 业务失败 | gRPC status + 稳定 detail；调用方按 code 处理，不解析 message |
| deadline / cancellation | 传播到上游并停止工作；已提交副作用按方法幂等/补偿契约解释 |
| required service 未 ready | Kernel 阻止对应 Ingress，不排入黑洞 |
| optional organ degraded | 撤销能力并更新 Projection；不伪装完整 ready |
| stream/data reference 失败 | 控制面显示失败/过期/取消；清理 lease 和临时资源 |
| 新链路切换失败 | 只在该切片明确回退窗口内恢复旧主线并保留诊断；修复后重新过门 |
| 平台级阻断 | 停止切片，由新 ADR 修改已接受方向；不得永久停在双轨 |

## 风险

| 风险 | 应对 |
|---|---|
| Protobuf DTO 污染领域层 | import 边界检查、Adapter contract test、代码审查门 |
| gRPC/Connect 语言插件能力不齐 | 先做三语言/双平台 spike，以固定版本和最小功能矩阵选型 |
| 本地端点被其他进程冒用 | 延续动态 catalog，并验证 owner PID、进程世代与平台认证 |
| Surface Gateway 变成万能业务层 | 只做 BFF/Projection 与受控 command，领域判断返回 owner |
| stream 缺少背压或取消导致内存增长 | 有界队列、flow-control、deadline、取消和长运行指标 |
| 媒体全部走普通 RPC 导致复制和延迟 | control/data plane 分离，基于大小/频率基线决定通道 |
| 双轨迁移长期化 | 每切片先写删除对象、owner、指标和完成门；未删除不得关闭切片 |
| JSON Schema 与 Protobuf 复制同一结构 | 契约归属清单、生成/引用规则和重复定义扫描 |
| 版本号跟随应用版本失控 | `glimmer.*.v1/v2` 与产品 SemVer 分离，Buf breaking 固定基线 |
| 迁移破坏 readiness 或监督权 | ADR-0009 contract test、崩溃/重启/停机矩阵和 Kernel 拓扑断言 |
| 生成与兼容门依赖托管服务 | Schema 全量入库、工具和插件版本固定、离线生成/`buf breaking` 门、供应链许可证与摘要清单 |
| transport/runtime 渗入领域模型 | Domain/Application/Port import 门；替换 gRPC/Connect 的 Adapter contract test 不允许修改领域模型 |

## 验收门

### 架构与物理形态

- `contracts/` 是唯一契约脊柱；Protobuf Service 与 JSON Schema 文档契约职责分明。
- `protocol/`、被替代的 ZMQ/stdio/手写 WebSocket 主线、旧配置、旧生成物和无期限桥接已删除。
- Kernel 是内部服务拓扑和 Surface Gateway owner；不存在器官横向发现/直连或 Surface 直连内部器官。
- 生成 DTO 只存在于 Adapter/transport 边界，领域层 import 门通过。
- gRPC/Connect 只出现在 Adapter/Transport/composition root；以测试替换默认 transport 时不修改领域模型与业务 Port。

### 兼容与跨语言

- Buf lint/breaking 对固定基线通过；破坏性变更只通过新世代和迁移计划进入。
- JSON Schema dialect、fixture 与 compatibility 门通过；同一消息无双事实源。
- TypeScript、Python、C# serialization round-trip 和所有 Adapter contract test 通过。
- 应用版本升级与 `v1/v2` 契约世代可以独立演进。
- 固定版本的 Buf/`protoc`/语言插件、JSON Schema validator 和生成链可离线复现；不访问 BSR 或其他专有云也能完成 lint、breaking、generate 和 round-trip。
- canonical `.proto`/JSON Schema 均在仓库，依赖许可证与摘要可审计；远程插件和托管 SDK 不是唯一来源。

### 生命周期与语义

- Command、Query、Event、Stream、Document 均有代表性端到端链路；无 `payload:any` 万能 envelope。
- 成功、typed failure、deadline、cancellation、trace、causation/correlation、readiness、generation mismatch 和幂等/补偿语义均有测试。
- Required/optional service 的 waiting/degraded/failed/restart/stop 投影与 Ingress 行为通过故障注入。
- ADR-0009 的动态回环端点、进程隔离、监督回收和真实 readiness 在 Windows/Linux 通过。

### Surface 与数据面

- Desktop/Web 只访问 Kernel Surface Gateway；浏览器认证、权限拒绝、断线、重连、背压、取消和状态矩阵通过。
- Audio/Avatar/Blob 数据面有实测阈值、资源上限、lease/stream 清理和长运行证据；大型数据不进入普通消息。
- 性能基线覆盖启动、首次调用、稳态延迟、吞吐、内存、CPU、包体和多实例。

### 工程与文档

- 受影响 typecheck、build、Python/C# 测试、跨进程集成、Desktop/Personal Server UI、安装和停机矩阵全部通过。
- Current、Implementation、Reference、Guide、SDK、打包和排障文档与代码一致；不再把目标写成未来，也不保留旧术语主入口。
- 迁移期观测指标归零，所有 feature flag、compatibility bridge、临时端点和测试进程已清理。
