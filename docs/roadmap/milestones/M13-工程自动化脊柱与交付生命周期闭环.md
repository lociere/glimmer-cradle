## 目标成果

```text
fixed source
  -> owner-local atomic task
  -> root thin orchestration
  -> local / PR CI
  -> fixed artifact
  -> install / ops transaction owner
```

公共任务必须可说明 `inputs`、`outputs`、`side effects`、`lock`、`idempotency`、
`confirm`、`dry-run`、稳定 `exit code`、脱敏诊断和 `cleanup/recovery`。Release 只消费
前序固定制品；查询不取得写锁；高风险动作缺确认时失败闭合。

## 范围与保护边界

- 范围：部署事务、备份/Smoke/DLQ、task graph/CI、owner-local tooling、Personal Server
  供应链、Desktop Windows packaging。
- 保护：M12 Contract Spine 与 runtime consumer 迁移、业务协议、人物/认知/Avatar 行为、
  UI、真实服务器/数据库/Docker daemon、Registry、Release、签名和公证。
- `contracts/` 与 `protocol/` canonical 内容及生成物未因 M13 改写。
- Unity runtime 仍位于 `core/avatar/unity-host/`；它到 `hosts/unity-avatar-host/` 的 runtime
  split 继续属于 M12 Slice 5。M13 D 只完成工程任务 owner-local 收口。

## Slice A：部署事务安全

- 唯一 owner：`deploy/personal-server/lib/host-transaction.sh`。
- 所有宿主写入口共享 `/run/glimmer-cradle/host.lock`；guard inode、FD、owner、mode、
  canonical path 和安全祖先共同防止伪造、symlink 与锁文件替换，PID 只用于诊断。
- `status/logs` 在 version、Docker elevation、token/env/state/权限初始化之前分流，只用当前
  用户权限查询 Docker。
- deployment env 把宿主 run root 只作为 bind source，应用与 Bridge 的 socket 规范路径固定为
  `/run/glimmer-cradle/ops-bridge.sock`；旧 host-path 值在写事务准备阶段迁移。
- Ops Bridge 写 durable request，等待 one-shot owner 持锁 ready，再以 operation/nonce
  compare-or-create ack；只有观察到 started 才返回 accepted。request/result/ack/decision 四件套
  持久化 `owner_timeout` 与规范终态，按 retention 一并清理；旧 bridge 回收不影响事务。
- Product API 与 Web 使用同一 `operation_id` 提交、查询和重连续查；HTTP 与 audit 区分
  unsupported/accepted/started/committed/failed/recovery_required/owner_timeout/conflict/error，
  失败与恢复必需状态不返回 200 或 succeeded。
- `update.apply` 在尚无经验证 candidate version/OCI digest/release source 到
  `install-release.sh` 的不可漂移绑定时明确 `apply_supported=false`，不返回假 accepted。
- backup/restore 补偿不能恢复操作前服务或数据时写入 `recovery_required`、精确
  `recovery_action` 并返回 78。
- installer 原样传播 deploy 的 70/75/78/130/143；只有外层补偿失败才升级 78。
- 执行阶段名为 `commit`，终态名为 `committed`。

## Slice B：数据与恢复安全

- `manual`、`transaction`、`restore-safety` 备份分根；history retention 只清理 transaction。
- Smoke 用 `fs.cp` 创建真实临时副本，拒绝 symlink/junction，退出后删除临时根。
- DLQ replay 只允许代码注册且 owner/source/state 匹配的 dispatcher；Kernel 的
  `kernel.event-bus.v1` 把原始事件写入 owner-local durable ingress，等 EventBus 发布成功后
  才返回绑定 source、record、event type、trace、payload digest、operation 与 dispatcher
  identity 的 receipt。legacy Cognition source 没有当前生产 writer，未注册时返回 66。
- resolve 需要确认且不产生 replay 标记；cleanup 只删除超过 retention 的 replay 成功记录。
- `show` 默认只输出脱敏摘要；raw payload/stack 需要 root 和 `--confirm`。

## Slice C：Task graph 与 CI parity

- package 重复 protocol prehook 已删除；root build 按依赖图只构建一次。
- `pnpm test` 不再隐含 Bash；Linux release fixture 使用显式 `:linux` 任务。
- `.github/workflows/pr.yml` 在 Windows/Linux 调用同一个 `pnpm check:pr`。
- encoding inventory 覆盖 contracts、deploy、workspace、ignore 与受支持文本类型。
- `prepare-runtime.mjs` 把 lockfile、Node toolchain、共享/package manifest 与上游实际 output
  digest 纳入 identity，并记录每个 output 的 path/size/SHA-256；不接受 input digest 代替
  dependency output。

## Slice D：Owner-local 工具收口

- Avatar helper/build test 归 `core/avatar/`；Unity 工程任务归
  `hosts/unity-avatar-host/`；Extension SDK staging 归 `packages/extension-sdk/`。
- Personal Server release/install/smoke/version 任务归 `products/personal-server/`；DLQ、
  telemetry、experience 分别归 Kernel/Cognition owner。
- root `scripts/` 只保留 `check-architecture.mjs`、`check-no-bom.mjs`、
  `launch-product.mjs`，旧 root 实现与 `scripts/lib/` 已删除。

## Slice E：可复现供应链

- Dockerfile base image 只接受 `@sha256:` 固定输入；CI 在构建前验证三项引用。
- tar/OCI 固定目录生成 `artifact-manifest.json`、`provenance.json`、组件/依赖级
  `sbom.spdx.json` 与明确 unsigned 的 `build-claim.json`；integrity verifier 必须接收独立
  expected commit/digest/builder。
- GitHub workflow 用固定 SHA 的 `actions/attest` 为 tar 与 OCI digest 建立 Sigstore identity；
  release job 下载前序 artifact 后用 owner verifier 与 `gh attestation verify` 复验，不现场构建。
- 现有 PS checksum、OCI identity、原子安装与回滚链继续保留。

## Slice F：Desktop packaging

- `products/desktop/scripts/package.mjs` 是 Windows x64、publish=false 的产品入口；
  `electron-builder` 精确锁定。
- clean Windows workflow 先用固定摘要的 Unity/Cubism 工具链和许可入口生成、attest Avatar
  owner fixed artifact；Desktop job 复验 commit/digest/attestation 后只消费该制品。缺许可、
  工具链、attestation 或制品时失败闭合。
- package 先准备 bundled Node、Python 3.12.13、locked Python dependencies、Kernel resolved
  dependencies，并验证 Kernel、Cognition、Audio、Avatar、Extension Host 与 native 六类
  staging；任一 projection 缺失即失败。electron-builder 只消费该 staging。
- 安装态 `packaged-paths.ts` 解析只读 resources 与用户 data/config/run，
  `packaged-supervisor.ts` 使用 bundled runtime 监督 Kernel/Cognition/Audio/Avatar/
  Extension/native 生命周期，支持 ready/degraded、停止与子树清理，不依赖 root
  `scripts/launch-product.mjs`。
- 输出固定为 `dist/desktop/<version>/windows-x64/`，包含 installer、unpacked component
  manifest、provenance、组件 SBOM 与 unsigned build claim；verifier 逐文件验证组件确实进入
  installer staging，并拒绝缺少真实 PE header/体积、`app.asar` 或正式 supervisor 物理入口的
  伪造 installer；GitHub Sigstore 提供外部身份锚。
- `.github/workflows/release-desktop.yml` 与 Personal Server workflow 完全独立，只上传固定
  artifact，不创建外部 Release。
- 当前未声明签名、公证、正式发布或其他平台支持；新增平台必须新建独立验证矩阵。
