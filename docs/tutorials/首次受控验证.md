# 从一次受控验证理解项目

> 适用场景：首次接手，希望验证本地代码和一个真实界面，同时理解当前项目的证据边界。
> 前置条件：已有符合仓库要求的开发依赖；缺失时先按本地开发环境准备。命令在仓库根执行。
> 事实依据：repo-checks、Personal Server package/Playwright config、现有 auth/accessibility fixture。
> 维护触发：工具链、构建依赖、fixture、测试名称或报告目录变化。

## 先得到一个可观察结果

运行 `git status --short` 并保留现有改动。查看 [当前系统](../architecture/current/README.md) 的相关关系：
Personal Server 的浏览器界面通过受控服务投影操作系统，截图本身不能证明真实模型、设备或安装态可用。

本路径使用现有临时测试 Host：loopback HTTP/gRPC、临时配置/数据与受控响应。
不运行 `pnpm dev`，不登录外部平台，不调用真实模型，不修改用户的运行数据。

## 1. 核验仓库工具

```powershell
pnpm --filter @glimmer-cradle/repo-checks test
```

预期测试全部通过。这证明工具的实际反例，不证明产品全链就绪；失败时保留首个错误和当前候选，
按 [文档/工具入口](../README.md) 定位，不更改断言来取得绿灯。

## 2. 准备界面依赖并构建当前 Web

首次安装后需要当前 Contract/SDK 构建入口，已有相同输入的产物可复用：

```powershell
pnpm --filter @glimmer-cradle/extension-sdk run build:with-deps
pnpm --filter @glimmer-cradle/personal-server build:web
```

预期 contracts/SDK 编译和 Vite Web 构建成功。缺失的依赖按 [本地开发环境](../how-to/本地开发环境.md) 处理；
该步骤不需要 Unity、麦克风、ASR 或云端 provider。

## 3. 在真实浏览器验证登录界面

```powershell
pnpm --filter @glimmer-cradle/personal-server exec playwright test tests/ui/visual.spec.ts tests/ui/accessibility.spec.ts --grep 'compact anonymous login|login and authenticated overview' --project=personal-server-narrow --trace on
```

预期两项测试通过：窄屏匿名登录与现有视觉基线一致，登录及认证后 Overview 通过指定 WCAG 标签的 axe 检查。
打开 `build/reports/playwright/personal-server/report/` 的报告，检查 trace 中 480×900 登录及 Overview 页面，
观察标签、内容容量与布局；axe 和截图不能证明所有键盘交互，焦点、错误和重试需在具体交互任务中另行操作验证。
测试启动的临时 Host 在用例结束后清理。

缺 Chromium 时，当前 package 的 `test:ui:install` 会下载浏览器；按当前安装授权与网络条件处理，
不要把缺浏览器报告成产品失败。端口冲突、旧产物和 fixture 错误先与产品缺陷区分。

## 继续做一个真实改动

现在已得到工具测试与产品 fixture 的浏览器证据。需要纯组件学习时可用 package 的 Storybook；
需要 logout/快速重登、表单或配置行为时，按 [UI 工具指南](../how-to/前端开发与UI验收.md) 选择实际场景。
进入设备、模型、跨 OS 安装或生产恢复前，另取相应环境和授权；本路径没有关闭这些门。

首次上手的成果是可重现的测试、真实界面及证据边界理解；项目目标和当前迁移接线继续按所属资料判断。
