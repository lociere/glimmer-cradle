## 选择直接证据

写清本次成果主张和一个能使错误实现失败的反例；简单文字/token 调整可用定向检查和直接观察，不加镜像测试。
类型、注册、进程存活、业务 ready、数据提交和体验需要不同证据。

| 改动/风险 | 优先证据 |
|---|---|
| 确定性逻辑 | 相关单元/回归反例；有真实代数性质时才考虑幂等/roundtrip/property-based testing |
| 服务、并发和生命周期 | 真实 owner 接线、可控 Clock/barrier、重复/取消/迟到、超时/stop 重试与资源释放 |
| wire、Document、公开 SDK | 唯一源生成、兼容和 TS/Python/C# 实际 consumer/mapper、合法及非法输入 |
| 持久化/迁移 | 临时真实库、旧/空/坏样本、commit/ACK 两侧崩溃、重开、单写者、原身份/unknown/outbox 恢复 |
| UI | 当前构建真实页面、受影响交互/焦点/视口/主题/失败与截图；组件和产品分别取证 |
| Electron/Avatar/音频/Native | main/preload/进程测试，加受影响 OS/设备/Unity/固定安装物；替身不等于实机 |
| AI 行为 | 确定性预算/权限/控制流、受控模型接线；实际质量另固定模型/输入/工具评估 |
| 权限与隐私 | 正确授权可用，非法输入/拒权/撤销/切代失败关闭；诊断不暴露 secret 或私人内容 |
| 打包、部署与恢复 | 固定制品与源/依赖、安装/升级/失败/回滚；开发 build 不关闭产品安装门 |
| 文档/Skill | 来源/状态/规则、文件链接/元数据及正反请求；沿实际任务取成果，静态 PASS 不证明行为质量 |

## 命令和运行边界

开发中先运行必要定向测试；最终源码/依赖/构建工具交付集中运行根 `pnpm typecheck`、`pnpm build` 和受影响行为门。
关键安全、恢复与破坏性切换门及时完成，具体 CI/initiative 要求继续适用，不因局部提交重复全量。

| 目的 | 当前入口 |
|---|---|
| 文档/指令 | `pnpm check:docs`、`pnpm check:encoding`；Skill 加 `pnpm check:skills` 与格式/行为检查 |
| 目录/依赖/冻结规范 | `pnpm check:architecture`、`pnpm check:target-layout`；文件增删按变更宪章同步视图和摘要 |
| Contract Spine | `pnpm contracts:generate`、`pnpm contracts:verify`；生成与兼容副作用先看 contracts manifest |
| TS 模块/Host | 根 `test:platform`、`test:conversation`、`test:capabilities`、`test:jobs`、`test:host`；需要时用实际包 runner 定向运行 |
| Python Cognition/Worker/Audio | 根 `test:cognition`、`test:cognition-worker`、`test:audio`；定向使用 `uv run --project <owner> --extra dev pytest ...` |
| UI | [UI 工具指南](前端开发与UI验收.md) 的构建、Playwright/Storybook fixture 与对应 package scripts |
| 工具/CI | `pnpm test:tooling` 或工具 workspace 的定向 tests；全仓回归入口 `pnpm test` |
| 设备/安装/运维 | 对应 [专项/发布指南](README.md)；先检查授权、运行根、实际副作用与恢复条件 |

上表是入口，不要求每项都跑。脚本中的前置 build、真实模型/设备、下载、外部消息、数据迁移和部署要实际核对；
优先临时数据与受控替身，测试 owner 收尾连接、进程和临时根。
源码/fixture 未变且构建输入相同的结果可复用；修改 UI 后先保证浏览器使用当前产物。
文档生成、目标树和摘要的触发条件只由[文档维护](文档维护.md#文件增删和受控目录)拥有，不把命令表当逐补丁清单。

Vite/Vitest 配置采用项目已有的 ESM 入口。遇到 CJS Node API 警告时在原命令用 `VITE_CJS_TRACE=true` 定位，
不使用 `VITE_CJS_IGNORE_WARNING` 隐藏；是否阻塞由实际支持/兼容要求判断，不用警告推导整个产品失败。

## 保存提交、验证批次与审查候选

| 单位 | 边界与作用 | 不代表什么 |
|---|---|---|
| 保存提交 | 已获提交授权、逻辑清楚且必要定向检查通过的局部进展；可细粒度保存 | 不自动触发全量验证、独立审查、task accepted 或推送 |
| 验证批次 | 一个可观察结果及紧耦合机制、消费者和必要反例，可含多次局部提交 | 不混入独立功能，也不为攒批延迟安全、恢复或破坏性切换所需验证 |
| 审查候选 | 批次范围收束后固定 base→候选 commit/tree；有 dirty 时明确路径/内容指纹、证据与环境 | 不按 commit 数量分配审查，也不以旧候选结论覆盖新行为 |

按一个可理解、可验证、可回退的结果定批，不设固定文件数或提交数。
开发中及时运行能区分对错的定向反例；在批次收束时合并有效结果，集中完成所需组合验证和高风险审查。
不同契约/owner 的独立结果宜分批；必须共同保证原子性、原身份或资源责任的修复不为小提交拆断证据。
若批次已有多个可独立验收结果或审查无法把握整体，先沿真实边界缩小，不积累成整阶段大审查。

## 失败与证据复用

分开产品、测试/fixture、旧构建、环境和需求理解错误；修正原因后重跑受影响门。
不得弱化断言、吞错或刷新视觉/兼容 baseline 来遮盖失败；baseline 仅在明确预期变化后审查更新。

重要证据记录候选（commit/tree 或准确 dirty 范围）、命令/输入、环境、结果与产物，简单任务可合一行。
分别报告 PASS、FAIL、未运行、环境阻断、复用和正常 skip；替身、真实设备、真实模型及生产证据明确区分。

复用按结果的实际输入和覆盖判断，不能只看全仓 HEAD 是否改变：

| 变化 | 复用与重跑 |
|---|---|
| 无相关输入变化；只是普通继续、上下文恢复或保存提交 | 复用可定位且覆盖充分的结果；不因会话、日期或 commit SHA 变化自动重跑 |
| 正文措辞、已有证据记录、无行为影响的格式 | 验该文档批次；无关产品测试/审查不失效，规范源字节变化仍同步摘要 |
| 源码、consumer、契约、配置、fixture、生成物、依赖或检查器变化 | 重跑依赖这些输入的验证；其他已证明独立的结果可复用，并说明依据 |
| 冲突整合、新组合、未覆盖风险或失败反例 | 验新的组合/原反例，按影响扩大范围；缺输入指纹或覆盖依据时补证，不能假定命中缓存 |
| 运行进程、权限、设备、外部服务等动态事实 | 重新观察受影响时点；历史健康/ready/PID 记录不能证明此刻状态 |

复用可以是一行“证据 E、相关输入未变、覆盖此主张”；不要求给每个文件生成新账本或每次重写完整环境。
根 typecheck/build 与最终大型门仍按固定候选集中完成，不能把复用当成取消门。
历史日志缺少输入/环境时不能直接计当前 PASS，测试存在也不能写成已运行。

## 独立审查

低风险局部工作可自查。权限、跨进程契约、异步生命周期、不可再生数据、架构 owner、发布/恢复等高风险候选，
按上述批次，在停止候选写入后由独立审查者核对真实链路和证据；同批关联修复集中复核最终候选。
不因一次低风险文字修正或保存提交额外发起独立审查。分工遵循既有授权，不创建用户会话代替许可。

审查者只读，从输入→授权→状态变更/提交→投影→撤销追踪实际可达反例。
finding 给位置、触发、影响、因果证据和修复方向，区分确认缺陷与疑点，说明是否阻塞本次成果。
发现多个关联 finding 时，执行 owner 可一并修复、重验受影响门，再停止写入并固定新的整个批次候选；不逐微差轮流修复/发审。
复审聚焦修复、失效证据和新增风险，同时确认先前结论仍覆盖该组合；风险或范围实质扩大时扩大审查。
只有无相关行为影响的附加文档/格式变化可保留原专业审查结论，并单独检查该变化。
外部建议同样核验。无法取得独立审查时报告缺少该门，不把自评改称独立结论。

## 接受与交付

长任务简述实际成果、已关闭门、具体剩余缺口、证据位置及下一动作；必要时补候选/句柄与阻断，不强制空模板。
简单修改可以一段交付，稳定背景与完整日志留在其权威位置。
未通过必要门不宣称接受；阶段结果、编译、行为测试、审查、提交、推送和上线分别说明。
环境不足时完成可独立的本地工作并指出缺少何种直接证据，不仅留下建议或伪写通过。
长任务恢复见 [长任务与恢复](长任务与恢复.md)，协作研究与评估仅在维护体系时读 [设计记录](../governance/agent-workflow-design.md)。
