# 开发工作流

适用任务：任意实现、调试、文档、审查或交付任务。本页唯一拥有**自适应任务流**：按风险和耦合组织工作，以有效吞吐、首次正确率、低返工、证据完整、决策可追溯及成本与风险成比例为目标。效率不等于最少步骤、token、会话、测试、文档或沟通。

验证范围、检查批次、阶段门和证据复用由[测试与交付](测试与交付.md)定义；角色、资源 owner、控制卡、交接和回报由[会话与任务编排](会话与任务编排.md)定义。本页不重复这些规则。

## 1. 准备与任务分级

1. 检查 `git status --short`，保留用户已有改动；创建分支时按 `docs/guides/development/命名规范.md` 选择工作性质与 scope。
2. 读取 `docs/README.md` 与 `docs/guides/开发手册.md`，再按任务进入 Blueprint、Current、Implementation、Reference 或 Guide；用 `rg` 找入口、owner、生产者、消费者、配置、测试和旧术语。
3. 冻结用户可观察目标、唯一事实源、生命周期 owner、跨边界契约、成功/失败/降级语义、风险清单与删除条件。
4. 按下表选择起始路径；路径随已证实的风险调整，不按 diff 或文件数机械升级。

| 路径 | 适用边界 | 连续工作与收束 |
|---|---|---|
| 低风险局部改动 | 单一 owner、无跨边界契约或不可逆影响 | 一个执行者端到端完成、定向检查与自查；默认不要求独立审查或全仓门。 |
| 普通单 owner | 受影响包或真实行为需要确认 | 在内聚工作片段收束时运行受影响包与真实行为门；是否审查按风险决定。 |
| 跨层高风险 | 架构、协议、生命周期、数据或安全 | 固定 candidate，覆盖真实故障门并进行独立增量审查；项目特定 slice 规则仍适用。 |
| 发布/生产 | 固定制品要进入外部环境 | 交由唯一环境 owner，在回滚门和环境授权下执行。 |

独立审查是跨层高风险或明确验收门的控制，不是每个候选状态的普遍要求。小改动允许直接闭环。

按改动类型补足必要事实源：字段或事件先读 `reference/protocol.md` 与 `implementation/Protocol契约层实现.md`；配置或路径先读 `reference/configuration.md` 或 `reference/data-layout.md`；runtime 先读 `current/03`、`current/05` 与 `implementation/Kernel与Runtime实现.md`；UI/Avatar 先读 `implementation/Desktop与Avatar实现.md` 与 `reference/ui-design-tokens.md`；Extension/Skill 先读 `reference/extension-sdk.md` 与 `implementation/Extension与SkillPlane实现.md`。

## 2. 内聚工作片段与自然收束点

默认按**内聚工作片段**连续实现，而不是每次编辑都中断检查。一个片段可以包含紧密关联的 Schema/Port、生产者、映射层、消费者和投影；跨层改动仍按这一依赖顺序推进，单层改动也覆盖空态、错误和释放路径。

以下任一完成时到达自然收束点：

- 完整契约与首批 consumers 已连通；
- 完整 lifecycle 已覆盖创建、ready/degraded/failed、restart/stop 或释放；
- 完整目录迁移、imports/composition 与删除门已闭合；
- 完整用户行为及其成功、失败或降级状态已闭合；
- 即将跨 owner、子系统、不可逆动作或外部环境。

片段中途只在继续会放大返工或丢失关键证据时提前检查：关键假设尚未证实、生成/编译/平台可行性未知、即将产生不可逆副作用，或延后会丢失失败证据。快速门按反馈价值选择，不是每次编辑必跑；具体选择见[测试与交付](测试与交付.md)。

## 3. 步骤契约与信息流

仅跨 owner、高风险、交接或需要决策的步骤，才在控制卡中保留以下完整契约；相邻步骤的输出必须成为下一步的输入。低风险、单一 `[执行]` 端到端任务不逐步填写重型控制卡：执行者只需在自身回报或验证账本记录目标、风险判断、验证和交付索引；没有总控时由该执行者持有此简化索引。

| 字段 | 记录内容 |
|---|---|
| 触发 | 为什么现在执行，例如自然收束、风险升级或外部授权。 |
| 输入 | 已确认的事实源、上一步产出、风险假设和有效证据。 |
| owner | 负责决策、写入、审查或环境操作的唯一角色。 |
| 动作 | 有边界的实现、检查、审查、迁移或交付动作。 |
| 产出 | 可被消费的代码状态、结论、制品、迁移结果或风险判断。 |
| 证据 | 可追溯的测试结果、报告、diff、日志摘要或环境观察。 |
| 失效条件 | 哪些代码、依赖、环境或假设变化会使产出不可复用。 |
| 下一入口 | 哪个片段、验证批次、审查、交付或用户决策消费该产出。 |

没有明确消费方的中间材料、检查或会话应删除或合并。但交付、验证账本、审计、事故追溯、合规和回滚所需证据可保留可追溯索引或报告位置，即使不进入下一实现步骤；不复制全文。控制卡只索引事实和证据，不替代事实源、验证账本或最终报告。

## 4. 执行与收束

1. 选择路径并建立第一个内聚片段；先实现能让后续消费者成立的事实源与 owner 边界。
2. 在片段内连续完成紧密改动；仅在第 2 节的提前检查触发器出现时中断。
3. 到自然收束点后，执行者对抗性自查边界、契约、生命周期、错误路径、删除门和文档影响；再按[测试与交付](测试与交付.md)选择定向验证批次。
4. 修复发现的问题，更新唯一权威文档，固定可追溯状态；若路径要求独立审查，则审查固定增量并只回传受影响 findings。
5. 将已确认产出作为下一片段输入；全部片段闭合后进入交付/PR 阶段，运行该阶段要求的门，不把它们误当作每个片段的重复动作。

架构升级必须同步物理形态：目录结构、文件名、配置键、Schema、加载链路、默认模板、测试和文档；删除被替代的旧入口、旧字段、旧 bridge、旧配置和无期限 fallback。

## 5. 升级、降级与停止

以下触发器出现时，升级风险路径并补齐相应 owner、证据和验证：跨进程契约、持久化或迁移、权限或 secret、不可逆副作用、readiness/restart/concurrency、安装或发布 consumer、生产环境。触发器缺失时不得机械套用大流程。

若事实证明风险边界较小、外部影响未发生且账本说明原因，可降回较轻路径；已触发的不可逆、外部或项目特定验收门不能仅因后续 diff 变小而撤销。相同策略连续两次无效时停止，核对事实源并缩小问题；需要产品取舍、owner 冲突、凭据或不可替代工具时按会话回报契约升级，不自行扩张范围。

真正阻塞只包括缺少用户必须决定的产品取舍、缺少无法替代的外部凭据/工具，或同一事实源连续核对后仍无法判断；任务范围大本身不是阻塞。阻塞时回报已查证内容、阻塞点、所需输入和可继续的最小下一步。

## 6. 交付前检查

- 没有覆盖用户原有改动，也没有遗留临时兼容、旧入口、旧字段或旧目录外壳。
- 事实源、物理形态和用户可见行为一致；文档不把未验证结论写成事实。
- 架构不变量变化已更新 Blueprint 或 ADR，实现落地更新 Current/Implementation，字段和路径更新 Reference，操作变化更新 Guide，未完成承诺进入 Roadmap。
- 每个片段产出有明确消费方，控制卡、验证账本和最终报告各自只保留其职责信息。
- 已运行、未运行及其原因、真实阻断和剩余风险均可追溯；没有为了省成本跳过必要设计、验证、文档、审查或高风险阻断说明。
