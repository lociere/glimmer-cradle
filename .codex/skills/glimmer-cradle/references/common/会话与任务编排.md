# 会话与任务编排

适用任务：所有总控、执行、审查、发布和生产运维会话。目标是让每个会话只有一个角色、每个里程碑只有一条决策链、每项独占资源只有一个 owner，并以正确性、首次正确率、证据完整和决策可追溯为前提消除无效工作。效率不是压缩必要设计、文档、审查、验证或风险沟通，而是避免重复读取、重复验证、无收益拆分和状态噪声。

## 1. 角色模型

`session_role` 只能取以下一个值；同一会话不得中途换角色。需要换角色时创建新会话并重新下发契约。

| `session_role` | 负责 | 禁止 |
|---|---|---|
| `[总控]` | 锁定范围与禁止项、指定 owner、维护里程碑状态、处理跨边界决策、消费结构化结果并最终验收 | 写代码、运行长时间测试、分析完整日志、直接发布或操作生产 |
| `[执行]` | 读取事实源、在授权边界内实现、维护验证账本、完成当前验收门并回报 | 自称总控、扩大里程碑、替总控决定产品或架构取舍、改其他执行者范围 |
| `[审查]` | 基于固定 commit/diff 做只读审查，报告缺陷、风险和验证缺口 | 修改被审查工作树、边审边修、接管实现或发布 |
| `[发布/运维]` | 对固定 commit/制品执行一次获授权的发布、部署、回滚或恢复矩阵 | 边发布边改代码、扩大目标环境、与其他会话共同操作同一发布流程或环境 |

小型任务可由一个 `[执行]` 会话端到端完成，无需人为增加总控层。会话按风险边界、耦合度和上下文健康划分，不按文件或微步骤机械拆分：同一 owner、紧密耦合且输入输出稳定的连续工作可由同一执行者持有；复杂且独立的风险边界可以拆分。只允许边界独立、输入输出稳定且不写同一事实源的任务并行。

在支持编辑会话标题的界面中，建议使用 `[总控]`、`[执行]`、`[审查]`、`[发布/运维]` 前缀；标题只是识别辅助，不代替 `session_role` 契约，也不假设所有工具都有标题能力。

## 2. 决策 owner 与资源 owner

- 同一里程碑最多一个决策 owner；有总控时由当前 `[总控]` 担任。执行、审查、发布/运维会话只能在下发契约内做局部技术判断。
- 创建执行、审查或发布/运维会话不等于更换总控；除非用户明确更换或总控完成换届，原总控默认继续任职。
- 一个工作树同一时间只有一个写入 owner。并行实现必须使用独立 worktree，且文件边界和集成顺序明确。
- 一个 Release、服务器、数据库迁移、生产环境或扩展发布过程同一时间只有一个操作 owner。
- 已有 active owner 时，新总控先接收其会话 ID、资源、状态和回报路径；新总控与新执行者都不得写入同一工作树或操作同一外部环境。
- 需要接管独占资源时，先要求原 owner 停止，确认命令、进程、工作树和临时资源状态，再显式移交；不得靠新会话直接覆盖。
- 长任务由启动它的 owner 等待、终止和清理。其他会话只消费紧凑快照，不重复启动。

## 3. 创建角色会话与更换总控

不要单独说“切换会话”，也不得先给通用切换提示、再在下一句补充角色。创建新角色和结束当前会话必须使用不同的强类型动作：

- `建议创建执行会话`：当前总控保留，向唯一执行 owner 下发新实现或验证任务。
- `建议创建审查会话`：当前总控保留，对固定代码状态进行独立只读审查。
- `建议创建发布/运维会话`：当前总控保留，向唯一环境 owner 下发固定制品操作。
- `建议现在切换到新会话（更换总控会话）`：当前总控发生上下文健康问题或用户明确要求换届；这是决策权交接，不是实现任务下发。
- 其他角色需要替换时使用 `建议现在切换到新会话（更换执行会话）` 等包含精确切换短语和目标角色的措辞，并先保护、停止和移交其独占资源。

里程碑完成、进入实现阶段或进入发布阶段，本身不要求更换总控。通常由原总控保留决策权，并创建相应角色会话。

总控发生上下文压缩或恢复摘要时，只触发一次快速会话健康复核，不单独、机械地触发换会话建议。复核应确认：

- 当前目标与范围是否清楚；
- 关键决策、决策 owner、资源 owner、验证账本和下一验收门是否可可靠追溯；
- 是否出现重复读取、理解偏差、无效调试、范围漂移，或日志、截图、diff、跨仓输出等噪声淹没有效上下文。

若复核通过，应继续当前总控会话。只有健康复核命中以下情况，或用户明确要求更换总控时，才建议更换总控：

- 关键决策、目标/范围、owner、验证账本或下一验收门已难以可靠追溯；
- 总控连续两次出现同一理解偏差、返工或无效调试；
- 大量日志、截图、diff 或跨仓输出已淹没总控所需的决策上下文；
- 总控持续承担实现、长时间测试、发布或生产操作，角色边界已经失守；
- 一份精简总控交接明显比继续重复读取更可靠；
- 用户明确要求更换总控。

未经用户同意不自动创建、归档或更换会话。建议前先保护当前工作状态，不执行 `reset`、`clean`、无关提交，也不中断必要命令。

## 4. 状态/证据交接包与新会话启动契约

状态/证据交接包是控制卡在一次具体交接上的 canonical 快照，仅用于创建或更换会话、跨 owner 移交、高风险工作、固定 candidate 审查或发布等真实交接边界。它不替代项目事实源、验证账本或 diff，也不要求低风险单执行者任务建立重型控制卡或独立审查。风险分级、内聚片段、自然收束点和升级/降级仍由[开发工作流](开发工作流.md)唯一拥有。

交接包必须分层，接收者不得把四层混成一份需要从头重证的背景材料：

| 层 | 必填内容 | 接收方式 |
|---|---|---|
| `confirmed_facts` | 已确认决策、范围、owner、事实源链接、适用条件与来源 | 默认直接消费；只在来源缺失、陈述冲突或后续证据反驳时独立追溯，不从对话历史重新推导。 |
| `fixed_state` | branch、base/candidate 完整 SHA、candidate tree、diff 边界、工作树状态、制品 digest、资源 owner 中与任务有关的项 | 启动时做最小可信校验；任何不一致都先停止正常写入或结论输出并回报。 |
| `validation_ledger` | 命令与范围、结果、证据位置、覆盖风险、绑定的代码/依赖/环境状态和失效条件 | 失效条件未触发时复用；失败证据用于定位，不伪装成通过；仍有效的昂贵成功门默认不重跑。 |
| `open_unknowns` | `unknown_id`、未证实假设/剩余风险/缺口、为何未决，以及引用的 `trigger_id` | 触发前不探索；触发后按 `reading_contract` 中同名 `trigger_id` 的映射行动，不在本层重复范围、上限或停止门。 |

直接消费 `confirmed_facts` 不等于盲信执行者：所有接收者都独立校验 `fixed_state`，审查者还必须独立形成结论并挑战高风险声明；区别只在于不重复发现已给出来源且没有反证的背景事实。高风险发现和真实阻断必须完整陈述并附可追溯证据，不受摘要篇幅限制。

每个交接包还必须包含 `reading_contract`；它唯一拥有初始读取集、扩读触发器到 `next_scope` 的映射、目录/文件/命令/输出/时间上限，以及停止门和回报门。默认初始集只包含交接包、任务必读 canonical 页面、目标 diff/文件和账本索引。默认触发器映射如下，具体任务可在 `reading_contract` 中收窄 `next_scope` 或新增 `trigger_id`：

- `state_mismatch`：fixed state、owner 或账本绑定状态不一致 → 只核对对应状态生成命令、owner 状态或账本绑定项；
- `source_conflict`：被引用事实无法定位、事实源互相冲突或实际证据反驳 `confirmed_facts` → 只读被引用 canonical 来源及其直接证据；
- `undeclared_impact`：diff 触及未声明 owner、跨边界契约、consumer、生命周期、安全或不可逆影响 → 扩到相关 owner、直接 producer/consumer 和目标测试；
- `risk_evidence_gap`：高风险声明缺少可追溯证据，或定向抽查出现反例 → 扩到该声明的一条关键契约/失败/生命周期链及其目标测试或日志片段；
- `target_check_failure`：定向检查失败、行为与交接结论不一致，或完成结论所需字段缺失 → 只读失败步骤的 owner、直接实现和相关日志片段。

`open_unknowns` 只能引用 `trigger_id`，不得覆写其条件、`next_scope`、上限或停止/回报门；单项确需不同策略时，在 `reading_contract` 新增专用 `trigger_id`。这样未知项只说明“什么尚未确定”，读取契约唯一决定“何时、读什么、读到哪里”。

命中触发器时先记录 `trigger_id`，再扩到 `reading_contract` 指定的一个相邻范围；没有映射、该范围没有产生相关证据或达到输出/时间上限时，按停止门冻结本轮扩读并转入缺口回报。`reading_contract.stop_gate` 只停止扩读，不自动终止整个任务或触发回滚等其他任务动作；是否终止任务、发布是否回滚等只由顶层 `stop_conditions` 决定。`reading_contract.report_gate` 只定义何时形成缺口回报及必报的 `trigger_id`、`unknown_id`、已读范围/已达上限、已有证据、仍缺事实和最小下一输入；回报对象、格式和频率一律引用顶层 `report_contract`。整库 inventory、完整任务历史、完整日志或无边界搜索必须有具体触发器、预期证伪目标和新的上限；不能以“更放心”为理由扩读。

每个新会话的首条提示必须显式包含：

1. `session_role`：四类角色之一。
2. `parent_controller`：下发或交接来源的总控会话 ID；没有总控时写 `none`。
3. 单一用户可观察目标和明确禁止项。
4. 必读事实源、允许修改边界和禁止依赖。
5. `handoff_packet`：上述 `confirmed_facts`、`fixed_state`、`validation_ledger` 和 `open_unknowns` 四层。
6. `exclusive_resources`：工作树、Release、服务器、数据库或生产环境及其现有 owner。
7. `authorized_actions`：允许写入、提交、测试、外部操作的精确范围。
8. `reading_contract`：初始读取集、`trigger_id → next_scope` 映射、目录/文件/命令/输出/时间上限，以及只冻结扩读的停止门和只形成缺口信息的回报门。
9. `context_policy`：默认 `fork_turns=none` 或有界 recent turns；若传完整历史，写明包与事实源无法恢复的具体决策及原因。
10. `stop_conditions`：越界、凭据缺失、owner 冲突、需要产品取舍或验收门失败时如何停止。
11. `report_contract`：回报对象、结构、频率和完成定义。
12. 推荐模型与推理等级；按复杂度选择，不默认最高或最低。

新会话先复述 `session_role`、目标、禁止项、独占资源和 owner；随后在任何写入或外部操作前，只对 `fixed_state` 做启动阶段的独立校验，不重建 `confirmed_facts` 的 inventory。字段缺失时先做安全的只读核对；不得假定自己是总控、写入 owner 或生产 owner。执行者发现目标需要跨越另一子系统、仓库、环境或里程碑时，按 `report_contract` 报告边界变化并停止扩张。

## 5. 总控换届

总控换届是显式的决策权转移：

1. 旧总控冻结新决策，整理交接摘要和所有 active 会话 ID/owner。
2. 新总控读取交接，确认角色边界、未决决策、active owner 和回报路径。
3. 新总控明确回复：自己不直接写代码、运行长时间测试、发布或操作生产。
4. 用户或既定授权确认接任后，新总控成为唯一决策 owner。
5. 旧总控停止下发、变更范围和最终验收；只转发换届前已在途的必要结果，不再形成第二决策链。

总控换届不暂停仍安全运行的执行任务，也不改变它们的资源 owner。新总控不得让新执行者碰触 active owner 的工作树或环境。

## 6. 执行任务下发

创建执行会话时，总控继续任职。执行者只取得明确资源和动作的授权，不取得里程碑决策权。总控维护控制卡（范围、关键决策、owner、风险、固定状态、验证账本和下一验收门），执行者直接读取项目事实源；控制卡用于消除重复转述，不替代设计、契约或证据。控制卡的步骤记录范围见[开发工作流](开发工作流.md)。

### 可复制：执行下发提示词

```text
session_role: "[执行]"
parent_controller: "<当前总控会话 ID>"

你是本里程碑的唯一执行会话，不是总控会话。
单一用户可观察目标：<一个可验收结果>

禁止项：
- 不扩大里程碑或修改其他执行者范围；
- 不替总控决定产品或跨边界架构取舍；
- 不触碰未授权工作树、Release、服务器或生产环境。

必读事实源：<AGENTS.md、项目 Skill、canonical references、必要 docs>
允许修改：<目录/文件>
禁止修改/依赖：<目录/系统/依赖>
handoff_packet：
- confirmed_facts：<范围、决策、owner、事实源链接、来源与适用条件>
- fixed_state：branch=<branch>；base=<完整 SHA>；candidate=<完整 SHA 或未提交 diff 标识>；tree=<tree SHA 或 none>；diff=<范围>；worktree=<状态>；提交权限=<允许/禁止>
- validation_ledger：
  - 可复用：<状态；命令；结果；证据；风险覆盖；失效条件>
  - 必须运行：<按风险排序的门禁>
  - 禁止重复：<仍有效的昂贵检查>
```

## 7. 审查任务下发

审查必须固定代码状态且默认只读；发现问题后回报总控，不得边审边修。审查独立性要求审查者独立形成结论，不要求从零发现范围、重建 inventory 或重新证明所有已确认事实。审查者先做最小可信校验：确认 base/candidate SHA 可解析且 tree 匹配，实际 diff 边界与声明一致，工作树和资源 owner 未变化，验证账本绑定同一代码/依赖/环境状态且失效条件未触发。任一项不一致时停止正常审查并报告，不以扩大搜索掩盖固定状态缺口。

最小校验通过后，只读增量 diff、直接 owner/consumer、风险相关事实和目标测试。高风险声明必须做定向抽查或反例挑战，例如沿一个关键契约、失败路径或生命周期声明核对实现与测试；这不是盲信执行者，也不是重跑完整探索。只有抽查发现矛盾、证据缺口、未声明影响或账本失效，才按 `reading_contract` 渐进扩读。仍有效的昂贵成功门默认不重跑；findings 一次性按严重度回传，修复后仅对受影响项聚焦复审。

## 9. 验证账本的会话使用

验证选择、检查批次、阶段门和证据复用规则由[测试与交付](测试与交付.md)权威拥有。本页只规定会话如何持有和交接账本：

| 字段 | 内容 |
|---|---|
| 状态 | branch、commit 或未提交 diff 标识 |
| 验证引用 | 账本条目、命令范围、结果、证据位置、风险覆盖与失效条件的链接或标识 |
| 下一门 | 消费该证据的片段、审查、交付或环境操作 |

执行 owner 更新账本，总控在控制卡中保留可决策的索引，并在需要交接时把索引绑定到状态/证据交接包；审查者和发布/运维 owner 复用有效证据。控制卡和交接包都不复制完整日志或报告；账本也不复制事实源。账本失效、fixed state 变化或 owner 冲突时按事件回报契约通知总控。验证如何选择、批次如何组织及证据何时失效仍只由[测试与交付](测试与交付.md)定义。

## 10. 状态、输出与交接

- 搜索先限定目录、文件类型和关键词；日志先看退出码、失败步骤和最后相关片段，再按需要扩展。证据留在验证报告或仓库事实源，回报只给可追溯链接与足以决策的信息密度；高风险发现与阻断不截断。
- 总控只接收结构化状态：完成项、改动文件、验证账本、阻断、风险、下一门和资源状态；不重复读取完整日志或实现。
- 回报由事件触发：候选状态、阻断、审查结论和完成。状态无变化时不轮询、不重复播报；等待长任务使用有界 wait 或紧凑快照。

任何角色交接摘要必须包含：

1. 当前 `session_role`、接任角色、`parent_controller` 和回报路径。
2. 当前目标、明确范围、架构决策和禁止事项。
3. 四层 `handoff_packet`，其中 fixed state 包含 branch、base/candidate、tree、diff、工作树和提交/制品状态。
4. active 会话 ID、独占资源、当前 owner、命令和临时资源状态。
5. `reading_contract`、`context_policy`、真实阻断、剩余风险和下一验收门。
6. 推荐模型与推理等级。
7. 对应角色的可直接复制提示词。

## 11. 反模式

- 用模糊的“切换会话”同时指代创建执行者和更换总控。
- 一个会话自称多个角色，或执行者在完成实现后自行接管总控验收。
- 总控和执行会话同时写代码，或多个执行者写同一工作树。
- 新总控忽略仍在运行的执行会话，重新下发第二 writer。
- 多个会话为同一问题各自读取整库、重跑相同验证并给出平行决策。
- 把独立审查误解为从零 inventory，跳过 fixed state 最小校验后重读完整历史、全库或完整日志。
- 在 `open_unknowns` 与 `reading_contract` 双写扩读条件、范围或停止门，使同一未知项产生两套可能漂移的读取规则。
- 交接包没有分层、来源、失效条件、扩读触发器或读取上限，导致接收者只能盲信或无边界探索。
- 把“最少上下文”“最少会话”或“最低成本模型”当成目标，遗漏完成任务所需的决策、风险、账本或独立审查。
- 没有固定 commit 就开始发布，发布失败后在生产环境现场改代码。
- 把“更多检查”当成严谨，却没有验证账本、风险映射、owner 和停止条件。
