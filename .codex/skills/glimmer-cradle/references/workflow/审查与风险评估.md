# 审查与风险评估

> 适用任务：独立 code review、设计风险自查、审查修复复核。
> 本卡拥有：形成独立结论的方法；验证范围与证据复用由《测试与交付》拥有。

## 1. 明确审查契约

确认目标、范围、固定对象、预期行为与具体门。明确本次属于设计审查、代码审查、自查或独立验收，并说明相应职责。

高风险候选由未承担该实现的审查者独立判断。审查者以只读方式检查固定候选，依据事实与验证证据形成结论，并如实记录已确认问题、覆盖限制和待验证项。

## 2. 以反例检验主张

1. 核对候选与交接范围，读取关键事实源和改动，而非从头重建全仓 inventory。
2. 对重要主张构造失败路径：非法输入、权限变化、竞态、部分失败、重启/恢复、旧 consumer、真实 Host 调用顺序。
3. 追踪唯一 owner、数据流和资源生命周期；检查测试是否真的经过该链路，是否使用当前产物，以及断言能否让旧缺陷失败。
4. 消费有效验证证据；只对覆盖缺口或怀疑点追加必要检查。既有有效证据可复用，新增检查范围依据证据缺口确定。
5. 形成可行动 findings 或有边界的“未发现阻塞问题”，注明未验证风险。

| 风险面 | 核心问题 |
|---|---|
| 用户成果 | 用户是否真的完成目标，空态/错误/状态反馈是否完整？ |
| 事实与 owner | 是否有第二事实源、反向依赖或越权推断？ |
| 生命周期 | 谁创建、持有、取消、关闭资源；迟到回调是否仍能写状态？ |
| 安全 | 非法/非导航请求、权限缺失、外部输入是否 fail closed？ |
| 物理收束 | 旧入口、桥接、字段及 consumer 是否真实删除或有退出条件？ |
| 证据 | fixture、测试与真实入口是否一致，是否只验证 happy path？ |
| 文档 | 声明是否超过实现与验证，是否复制/冲突另一权威源？ |

## 3. 报告与复审

每个 finding 给出位置、触发条件、具体影响、因果证据与修复方向；区分确认缺陷和待证假设。P0 表示紧急严重影响，P1 表示重大风险，P2 表示需要修复的普通问题，P3 表示低影响改进；同时说明问题是否阻塞本次目标、判断理由和必要修复范围。

复审以已固定修复、新风险和相关失效面为边界。关闭 finding 时应依据代码或测试证据说明原问题已消除。若修复涉及共享 owner 或新增高风险链路，应扩展相应审查范围。

用户明确停止或跳过审查时尊重其动作边界，但如实标记缺少独立结论，不声称已经通过项目接受门。

## 4. 流程质量评估

流程质量评估应检查目标清晰度、决策依据、分工适配性、行为验证覆盖、证据有效性和反例充分性，并结合实际结果分析成本与返工来源。

场景推演用于检查规则一致性和适用性；真实智能体效果通过代表任务的结果、缺陷、干预、恢复能力与成本共同比较。方法见 [智能体工作流设计](../../../../../docs/guides/development/智能体工作流设计.md)。
