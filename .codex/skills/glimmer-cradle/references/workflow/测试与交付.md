# 测试与交付

> 适用任务：选择验证、记录与复用证据、固定候选、验收和交付。
> 本卡拥有：证据选择与失效规则；具体命令入口见项目测试指南和实际 package scripts。

## 1. 从完成条件选择证据

验证应能够识别违反完成条件的实现。依据用户行为、跨边界不变量和高风险失败路径，选择具有充分覆盖的证据链。

| 验证目标 | 主要证据 | 覆盖限制 |
|---|---|---|
| 类型/格式/静态依赖正确 | 编译器、编码与架构检查 | 功能行为另行验证 |
| 分支逻辑与边界正确 | unit、合法/非法输入、回归反例 | 正常路径和异常路径分别覆盖 |
| 真实 owner 与调用顺序正确 | integration/真实 Host 测试 | helper 测试限于局部逻辑 |
| 用户能完成任务 | 真实界面交互与状态检查 | 构建与静态截图仅提供部分证据 |
| 视觉与可访问性符合目标 | 人工检查、代表视口、键盘/焦点、自动 a11y | 像素差异与交互质量分别评估 |
| 生命周期与安全边界成立 | 超时、拒权、重复、断连、重登与资源计数 | 需要覆盖异常时序与资源归属 |
| 规则/文档自洽 | 来源核对、链接、反例场景推演 | 实际执行效果通过任务评估确认 |

## 2. 执行范围与时机

开发阶段运行定向检查；相关输入稳定后，运行对应的交付验证矩阵。

- 源码、依赖或构建配置交付：根 `pnpm typecheck`、`pnpm build` 为基线；按影响运行 package 测试和架构/编码检查。具体 CI、PR 或 milestone 已约定的额外门仍需满足。
- 纯文档与 agent 指令：检查事实、相对链接、编码、规则冲突、指令路由和场景可执行性；Skill 元数据改变时验证其格式。纯文档验证范围限于上述检查；可执行脚本或配置语义变化时，追加对应运行验证。
- 契约：生成与验证 Schema，覆盖 producer/consumer 及非法输入，检查旧字段/入口残留。
- Cognition：在 `core/cognition` 执行 `uv run pytest -q`；Audio、Avatar、Extension 等按实际 owner 的专门指南补门。
- UI：验证真实产品入口、受影响状态、目标视口、交互/a11y 与必要视觉证据；组件工作台提供组件级证据，产品行为通过真实入口验证。源码改变后先确认测试使用当前构建；更新基线前应确认变化符合设计并排除回归。
- 生命周期/权限：覆盖 teardown 后异步回调、取消、重连、快速重复操作和真实资源归属；通过资源状态与行为观测确认清理结果。
- 迁移/发布：验证备份与恢复、旧样本、幂等、安装路径、ready/degraded 和退出回收；没有生产授权时只交付对应环境的证据。

失败先定位产品、测试或环境 owner。不得降低断言、吞错、改 warn 或随意刷新 baseline 来制造通过；确属测试缺陷时修正它并解释为何新断言仍覆盖风险。

## 3. 最小证据记录

每项重要证据记录：被验证输入（commit/tree 或明确 dirty 范围）、命令/场景、结果、相关环境与依赖、需要保留的日志/产物位置、失效条件。简单任务合成一行；跨 owner 或高风险任务保留可引用记录，不强制全套字段模板。

结果区分 PASS、FAIL、未运行、环境阻断和复用；正常 skip 必须说明适用条件。命令退出码用于说明对应命令的结果；体验与生产结论应有相应环境证据。交接日志应保留可定位片段，并完成密钥和用户隐私脱敏。

固定候选以 commit/tree 最清楚；dirty 候选也必须说明准确范围与同时写入是否停止。审查或验证期间内容变化，需要重新界定对象。提交/推送/部署是不同状态，不相互代替。

## 4. 证据复用与失效

证据复用依据被验证输入、依赖关系、覆盖范围及相关环境判断。

- 输入 tree、依赖和相关环境相同，且命令覆盖目标时，可复用；只改 commit 身份而内容相同不自动使内容证据失效。
- tree 不同时，追踪改动的 producer、consumer、配置、fixture、生成物和共享状态。仅证明相关输入未变时才能复用该项。
- 文档文字通常不使产品行为测试失效；文档路径变化会使相对链接证据失效。共享 controller、认证、路由或 token 变更应检查所有受影响的消费面。
- rebase/cherry-pick 冲突处理、合并后的组合、锁文件、浏览器/字体、环境配置或测试归一逻辑改变时，重验对应面；无法判断影响时运行能消除疑问的检查。
- “无残留进程”“服务健康”是时点证据；新的进程或环境变化后需复核。日历时间本身不使纯源码证据失效，但外部服务与安全状态可能已变化。
- 历史证据缺少输入、覆盖范围或环境依据时，应先记录缺口并补充验证，再判断其对当前候选的有效性。

审查者应独立检查既有证据的充分性，并对缺口追加验证；有效证据可直接复用。

## 5. 验收与交付

高风险包括认证/权限、异步生命周期、跨进程契约、不可再生数据、共享架构 owner 与发布边界。此类候选应独立审查，具体方法见《审查与风险评估》。审查修复只重验受影响面，复审聚焦 finding 与新引入风险；可直接证明的低风险收尾可定向复核，具体里程碑要求的审查门继续适用。

最后按用户需要说明：完成成果、验证与覆盖、未运行原因、剩余风险、Git/部署状态及下一步是否需要授权。过程日志通过必要摘要和证据位置引用。未通过必要门的成果标记为待验候选；用户要求停止验证时，停止追加检查并如实记录未验状态。
